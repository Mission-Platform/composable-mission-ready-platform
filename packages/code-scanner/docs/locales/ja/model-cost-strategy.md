このドキュメントは、ZXING ブラックボックス コーパス作業に要求された **モデル階層化マトリックス** をキャプチャします (「エージェントの使用」
さまざまなモデルを使用して、最も効果的なコストでこれを達成する最善の方法を決定します。」)どのモデル層が最適であるかを記録します
各納品段階に適しているため、委任メカニズムが存在する場合はどこでも、作業を最も安価なところにルーティングできます。
有能な層 — 単一のエージェントが作業を行う場合、最も労力がかかる (そして最も有能なモデルが) 場所をガイドします。
費やす必要があります。

## 階層の定義

- **Tier A (トップ / 最も有能)** — 新しいコンピューター ビジョン推論とスペックを重視したデコード: 新しいロケーター (MaxiCode)
  六角形グリッド + ブルズアイ、PDF417 行クラスタリング、GS1 DataBar 積層行アセンブリ)、およびリードソロモン /
  エラー訂正計算 (PDF417 の場合は GF (929)、MaxiCode の場合は GF (64)、RSS 組み合わせ論)。これらは最も重要な部分です
  微妙な点で間違っている可能性が高く、悪い初稿から回復するのは最も困難です。
- **Tier B (mid)** — ZXING リファレンスからの明確に指定された移植: シンボル テーブル、エンコーダー、生成されたラウンドトリップ
  テスト、ハーネス ロジック、および PNG ローダーの一般化。答えの形はわかっています。仕事は慎重です
  転写と配線。
- **Tier C (安価/機械的)** — 一括コピー、帰属ファイル、ベースライン スキャフォールディング、ドキュメント、および配線ボイラープレート
  (フォーマットタグ、`FORMAT_NAMES`、`ScanFormat` 共用体)。

## ステージ→階層マッピング

| ステージ                                               | 仕事                                                                   | 階層 |
| ------------------------------------------------------ | ---------------------------------------------------------------------- | ---- |
| 1 ベンダー コーパス + ローダー + ハーネス              | コピー/帰属 (C)、ローダー + ハーネス ロジック (B)                      | C→B  |
| 2 サポートされているフォーマットの読み取り速度を上げる | ロケーターの調整 + パスの再試行                                        | A→B  |
| 3 GS1 DataBar ファミリ                                 | テーブル/エンコーダー (B)、RSS-14 ロケーター + RS (A)                  | A/B  |
| 4 PDF417                                               | テーブル/エンコーダー (B)、行スキャン ロケーター + GF(929) EC (A)      | A/B  |
| 5 マキシコード                                         | 16 進グリッド ロケータ + GF(64) RS (A)、テーブル (B)                   | A/B  |
| 6 接続 + JS + ドキュメント                             | ボイラープレート/ドキュメント + 配線 (C)、wasm リビルド + スモーク (B) | C→B  |

## 原価主義

Tier-C / Tier-B のシェアを最大化します。機械的な移植 (テーブル、エンコーダ、往復テスト、配線) が大部分を占めます。
新しい形式の作業 — そして、3 つの真に新しいロケーターとそのエラー修正のために Tier-A 予算を確保します。
数学では、弱いモデルの間違いを検出して修正するのにコストがかかります。短いスパイクは、より安価なモデルのベンチマークとなる可能性があります。
1 つのデコーダ ポートを作成してから、残りの層をコミットします。

## どのように展開したか

- **ステージ 6** (このステージ) は最も明確な Tier-C→B ケースです: 拡張
  `FORMAT_NAMES` と `ScanFormat` 結合は機械的 (C) です。 wasm を再構築し、アップロード/ストリーム スモークを作成する
  小型の PNG リーダーを備えたスイートは、十分に仕様が定められた中間層の作品 (B) です。ネイティブになったら、Tier-A の推論は必要ありません。
  デコーダー (ステージ 3 ～ 5) が設置されていました。
- **ステージ 3 ～ 5** はそれぞれきれいに分割されました。ZXING テーブル/エンコーダーとラウンドトリップ テストは Tier-B 転写でしたが、
  ロケーターとリードソロモン (GF (929)、GF (64)、RSS 組み合わせ論) が Tier-A コアであり、マトリックスと一致しています
  上。

> 実装中にはカスタム エージェント委任ツールが利用できなかったため、
> 単一のエージェントが、このマトリックスに従って労力を費やしながら作業を実行しました。の
> マトリックスは、複数のグループへの委任が行われる将来の再実行のガイドとして残ります。
> モデル階層が可能です。
