# העבר לצינור FWS בטוח כברירת מחדל

תרגום בסיוע מכונה מהמקור האנגלי הקנוני. יש לבדוק ידנית בעת הצורך. שמות חבילות, פקודות, נתיבים ומזהים טכניים נשארים ללא שינוי.

> packages/flint/core/docs/guides/migration-v1.md: [packages/flint/core/docs/guides/migration-v1.md](../../../guides/migration-v1.md)
> שפה: עברית (he)

מדריך זה מיועד למודולי FWS שנכתבו לפני מקומיים בלתי ניתנים לשינוי, הלוואות מפורשות,
ומטא-נתונים של גבולות-מדיניות נבדקו הפכו לחלק מחוזה v1.

## Make mutation explicit

הוסף `mut` למקומונים ולפרמטרים שהוקצו. הוסף `&` עבור קובץ בלתי משתנה
לווה ו-`&mut` עבור הלוואה ניתנת לשינוי; הלוואות הניתנות לשינוי אינן יכולות לחפוף.

```flint
fn increment(mut value: i32) -> i32 {
  value = value + 1;
  value
}

fn inspect(values: &Vector<i32>) -> i32 { values[0] }
fn update(values: &mut Vector<i32>) -> unit { values[0] = 1; }
```

אל תסתמך על בעלות משוערת. ערכי POD מועברים לפי ערך כברירת מחדל;
ערכי שאינם POD משתמשים בהפניות בלתי ניתנות לשינוי. לִשְׁמוֹר `owned`, `borrowed`, ו `shared`
על גבולות ABI שבהם יש אחריות ספציפית לכל החיים או לשחרור
נדרש. לא ניתן להחזיר אזור זמני או לאחסן אותו בטווח ארוך יותר
ערך ללא גבול בעלות/קידום מפורש.

## בחר ובקר את מדיניות הגבולות

בדיקות גבולות זמן הריצה נשארות ברירת המחדל:

```bash
flint compile src/main.flint --bounds-checks runtime --format json
```

השתמש ב-`proven-safe` רק כאשר ניתוח מוכיח כל גישה מאורך האיסוף
ועובדות טווח אינדקס. `excluded-by-profile` הוא מהדורה מפורשת וניתנת לביקורת
בחירה, לא קיצור דרך לאינדקסים לא ידועים:

```bash
flint check src/main.flint --bounds-checks proven-safe --optimizer-report
```

סקור את ממצאי הניתוח ואת מדיניות המניפסט לפני המשלוח. לא ידוע או
אינדקסים לא מהימנים צריכים להשתמש ב-`runtime`; ניתוח קפדני דוחה מדיניות לא בטוחה
בקשות.

## בדוק מטא נתונים של מטמון שנוצר

מטמון המהדר עשוי להכיל `<key>.sonir.json`, סיכום דטרמיניסטי של
גרף Sea-of-Nodes האופטימלי. בדוק אותו מבלי להפעיל קוד אורח:

```bash
flint inspect-sonir .cache/main.sonir.json --format json
```

החפץ מתעד סכימה ושפה/גרסאות ABI, מקור וגיבוב גרפים,
מצב אופטימיזציה, מדיניות גבולות, אפקטים, מטא נתונים של בעלות, טווחי מקור,
והזמין דוחות מעבר. מעופש, פגום, גדול מדי או לא תואם מדיניות
מתעלמים מחפצים וניתן להסירם בבטחה.

## הקלדה סטטית קפדנית והיעדר טיפוסים דינמיים

פלינט היא שפה מודפסת סטטית עם פריסת זיכרון דטרמיניסטית ואפס השתקפות זמן ריצה תקורה. השפה אינה תומכת בסוגים מובילים דינמיים כמו `any` או `unknown`.

ניסיון להוסיף הערות לסוגים עם `any` או `unknown` מייצר `FLINT-TYPE-020` אבחון בזמן הידור. כדי להעביר קוד מסביבות דינמיות:

- החלף ערכים דינמיים בפרימיטיבים בטון (`i32`, `u32`, `f64`, `bool`, `string`, `bytes`).
- השתמש בפולימורפיזם פרמטרי/גנרי (`Vector<T>`, `Option<T>`, `Result<T, E>`) עבור אלגוריתמי מיכל הניתנים לשימוש חוזר.
- השתמש בסוגי נתונים אלגבריים מתויגים (`enum`) עבור ייצוגי תחום פולימורפיים.
- עבור מצביעי C ABI ונקודות אחיזה אטומות, הכריז על `opaque foreign type Handle;` במקום מצביעים לא מודפסים.
- ב-Web IDL bridges ו-bindings, ספק מיפוי סוגים מפורשים באמצעות `FlintBindingOptions.customTypeMappings`.

## התנהגות זיכרון ושחרור

ערכים בהיקף משתמשים באזורים מסומנים. ערכים שדורשים יותר מאזור משתמשים במפורש
ARC/ידיות משותפות; לכל ידית שמור יש שחרור תואם אחד, ומחזוריות
אינם מתקבלים במרומז. `fws_alloc` גולמי, `fws_realloc` ו-`fws_dealloc`
להישאר הגבול ה-ABI שנבדק בבעלות המתקשר. השעיה אסינכרון ואיטרטור הוא
גבול מילוט, ולכן יש לשמור במפורש על ערכים המשמשים לאחר ההשעיה.
