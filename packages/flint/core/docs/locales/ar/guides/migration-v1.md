# قم بالترحيل إلى خط أنابيب FWS الآمن افتراضيًا

ترجمة آلية مساعدة من المصدر الإنجليزي الأساسي. تُراجع يدويًا عند الحاجة. تبقى أسماء الحزم والأوامر والمسارات والمعرّفات التقنية دون تغيير.

> packages/flint/core/docs/guides/migration-v1.md: [packages/flint/core/docs/guides/migration-v1.md](../../../guides/migration-v1.md)
> اللغة: العربية (ar)

هذا الدليل مخصص لوحدات FWS المكتوبة قبل الوحدات المحلية غير القابلة للتغيير، والاستعارات الصريحة،
وأصبحت البيانات التعريفية لسياسة الحدود التي تم التحقق منها جزءًا من عقد الإصدار الأول.

## جعل الطفرة واضحة

أضف `mut` إلى السكان المحليين والمعلمات التي تم تعيينها. أضف `&` لملف غير قابل للتغيير
الاقتراض و`&mut` للاقتراض القابل للتغيير؛ لا يمكن أن تتداخل الاقتراضات القابلة للتغيير.

```flint
fn increment(mut value: i32) -> i32 {
  value = value + 1;
  value
}

fn inspect(values: &Vector<i32>) -> i32 { values[0] }
fn update(values: &mut Vector<i32>) -> unit { values[0] = 1; }
```

لا تعتمد على الملكية المستنتجة. يتم تمرير قيم POD حسب القيمة بشكل افتراضي؛
تستخدم القيم غير POD مراجع غير قابلة للتغيير. احتفظ بـ `owned` و`borrowed` و`shared`
على حدود ABI حيث يكون هناك عمر محدد أو مسؤولية الإصدار
مطلوب. منطقة مؤقتة لا يمكن إرجاعها أو تخزينها لفترة أطول
القيمة بدون حدود واضحة للملكية/الترويج.

## سياسة اختيار وتدقيق الحدود

تظل عمليات التحقق من حدود وقت التشغيل هي الوضع الافتراضي:

```bash
flint compile src/main.flint --bounds-checks runtime --format json
```

استخدم `proven-safe` فقط عندما يثبت التحليل كل وصول من طول المجموعة
وحقائق نطاق الفهرس. `excluded-by-profile` هو إصدار واضح وقابل للتدقيق
اختيارًا، وليس اختصارًا لفهارس غير معروفة:

```bash
flint check src/main.flint --bounds-checks proven-safe --optimizer-report
```

مراجعة نتائج التحليل وسياسة البيان قبل الشحن. غير معروف أو
يجب أن تستخدم الفهارس غير الموثوق بها `runtime`؛ التحليل الصارم يرفض السياسة غير الآمنة
طلبات.

## فحص البيانات التعريفية لذاكرة التخزين المؤقت التي تم إنشاؤها

قد تحتوي ذاكرة التخزين المؤقت للمترجم على `<key>.sonir.json`، وهو ملخص محدد لـ
الرسم البياني الأمثل لبحر العقد. قم بفحصه دون تشغيل رمز الضيف:

```bash
flint inspect-sonir .cache/main.sonir.json --format json
```

تسجل الأداة المخطط وإصدارات اللغة/ABI، وتجزئات المصدر والرسم البياني،
وضع التحسين، سياسة الحدود، التأثيرات، بيانات تعريف الملكية، امتدادات المصدر،
وأمرت تقارير المرور. قديمة أو مشوهة أو كبيرة الحجم أو غير متطابقة مع السياسة
يتم تجاهل القطع الأثرية ويمكن إزالتها بأمان.

## كتابة ثابتة صارمة وغياب الأنواع الديناميكية

Flint هي لغة مكتوبة بشكل ثابت مع تخطيط ذاكرة حتمية وصفر انعكاس في وقت التشغيل. لا تدعم اللغة الأنواع العليا الديناميكية مثل `any` أو `unknown`.

تؤدي محاولة إضافة تعليقات توضيحية إلى الأنواع باستخدام `any` أو `unknown` إلى ظهور تشخيص وقت الترجمة `FLINT-TYPE-020`. لترحيل التعليمات البرمجية من البيئات الديناميكية:

- استبدال القيم الديناميكية بأوليات ملموسة (`i32`، `u32`، `f64`، `bool`، `string`، `bytes`).
- استخدام تعدد الأشكال / الأدوية البارامترية (`Vector<T>`، `Option<T>`، `Result<T, E>`) لخوارزميات الحاوية القابلة لإعادة الاستخدام.
- استخدام أنواع البيانات الجبرية ذات العلامات (`enum`) لتمثيل المجال متعدد الأشكال.
- بالنسبة لمؤشرات C ABI ومقابض المضيف غير الشفافة، قم بتعريف `opaque foreign type Handle;` بدلاً من المؤشرات غير المكتوبة.
- في جسور وروابط Web IDL، قم بتوفير تعيينات نوع واضحة عبر `FlintBindingOptions.customTypeMappings`.

## سلوك الذاكرة والإفراج

تستخدم القيم المحددة المناطق المحددة. القيم التي تتجاوز عمر المنطقة تستخدم الصريحة
ARC/المقابض المشتركة؛ يحتوي كل مقبض محتفظ به على إصدار ودورات مطابقة واحدة
لا يتم قبولها ضمنا. الخام `fws_alloc` و`fws_realloc` و`fws_dealloc`
تظل حدود ABI المحددة المملوكة للمتصل. تعليق غير متزامن ومكرر هو
حدود الهروب، لذلك يجب الاحتفاظ بالقيم المستخدمة بعد التعليق بشكل صريح.
