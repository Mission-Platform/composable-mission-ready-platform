# Forge Web Script v1

תרגום בסיוע מכונה מהמקור האנגלי הקנוני. יש לבדוק ידנית בעת הצורך. שמות חבילות, פקודות, נתיבים ומזהים טכניים נשארים ללא שינוי.

> packages/forge-web-script/docs/reference/language.md: [packages/forge-web-script/docs/reference/language.md](../../../reference/language.md)
> שפה: עברית (he)

Forge Web Script (`.fws`) היא שפה קטנה לשימוש כללי עבור WebAssembly
עומסי עבודה. זה אינטרנט ראשון, מבוסס יכולות ובלתי תלוי בכוונה
Vue, React, ה-DOM ומהדר רכיבי Forge. מסמך זה הוא ה
חוזה שפה ומודולים סמכותי v1. `@mission-platform/forge-web-script`
הוא חזית התאימות בטוחה לדפדפן לניתוח, בדיקת סוגים, גרף/קישור
רזולוציה, נתוני מניפסט וממשק ה-API של שירות המהדר המשמש את מתאם Vite
ו-LSP. `@mission-platform/forge-web-script-wasm` הוא הקצה האחורי הדטרמיניסטי
שמוריד את ה-IR שנבדק ל-WebAssembly ו-WAT מאומתים. Node בלבד
חבילת `@mission-platform/forge-web-script-cli` מספקת את `forge-web-script`
פקודה לבדיקה והידור של קבצים או גרפי מקור. ה-TypeScript
החבילה מכילה גם את אביזרי ההתאמה להפעלה.

## סטטוס וניהול גרסאות

החוזה הנוכחי הוא **גרסת שפה `1.0`** ו**גרסת ABI לוגית
`1.2`**. גרסת השפה מתארת ​​מקור וסמנטיקה; גרסת ABI
מתאר את גבול ה-WebAssembly ואת פרוטוקול המארח. הם בעלי גרסה
באופן עצמאי. מהדר חייב לכתוב את שתי הגרסאות לכל מודול שנוצר
מניפסט, ומטען חייב לאמת את שניהם לפני מופע. ABI `1.2` הוא א
שבירת גרסה של חוזה הזיכרון: מניפסטים של `memory` חייבים להצהיר
`allocatorExport: "fws_alloc"`, `deallocatorExport: "fws_dealloc"`, ו
`reallocatorExport: "fws_realloc"`, בעוד `fws_reset` חייב להיות קיים ב-
סט ייצוא מודול. הטעינים דוחים מניפסטים ומודולים ישנים או לא שלמים
במקום להניח בשקט את המחלק מחדש החסר.

פורמט המקור הוא טקסט UTF-8 עם סיומת `.fws`. קובץ מקור הוא א
מודול מוגדר קובץ; הזהות שלו נגזרת מזהה הקובץ המנורמל Vite
(או נתיב יחסית למרחב העבודה). קלט המהדר מזהה את גרסת השפה, בעוד ה-
מניפסט שנוצר הוא סמן הגרסה המתמשכת הנצרך על ידי מטמינים. עתיד
גרסאות עשויות להוסיף פרגמת מקור, אך v1 אינו מצריך אחת; מהדר v1
חייב לדחות מבנה מקור שהוא לא מבין במקום לנחש אותו
גרסה.

## ניתוח מקורות ומדיניות שחרור

חבילת הליבה חושפת חוזה ניתוח אחד עבור המהדר, שפה
שילובי שירות, CLI ו-MCP. `analyzeForgeWebScript` מקבל את המסומן
תוצאת חזית וכללים רשומים אופציונליים, ולאחר מכן מחזיר עובדות, ממצאים ו
אותה אבחון יציב המשמש את שאר המהדר. הקשר ניתוח
כולל קבצי מקור, ערכי מפת מקור אופציונליים, IR גולמי ומוטב, את
מניפסט ABI, מטא נתונים של גרפים/קישור, פרופיל היעד ומדיניות מנורמלת.

ממצאי הניתוח משתמשים בקודי `FWS-ANALYSIS-*` יציבים וכוללים קטגוריה,
חומרה, טווח מקור תואם UTF-16, ראיות, רמז לתיקון ו
הפניות אופציונליות של OWASP/CWE. האבחון שלהם להוסיף `phase: "analysis"` ו
מטא נתונים אבטחה מבלי לשנות את `FWS-LEX-*`, `FWS-PARSE-*`,
אבחון `FWS-TYPE-*`, או `FWS-ABI-*`.

קומפילציה משתמשת בפרופיל המחמיר כברירת מחדל. במצב קפדני, חומרת השגיאה
ממצאים (או ממצאים מסומנים במפורש `blocking`) מונעים פלט Wasm ו-ESM;
הדוח המלא נשאר זמין על החפץ שהוחזר. הפיתוח
הפרופיל מיועד לתהליכי עבודה של עורך וחקירה: הוא מדווח על ממצאים
אך אינו משתמש בהם כשער שחרור. המדיניות כוללת יכולת מפורשת
רשימת ההיתרים ומגבלות מוגבלות לממצאים, עומק שיחה, לולאות, הקצאות, אסינכרון
משימות, וקלט ביטוי רגיל.

מפתחות מטמון של שירות מהדר כוללים את מדיניות הניתוח המנורמלת, רשומה
מזהי כללים, וקלט מפת מקור. שינוי כל אחת מתשומות הניתוח הללו
לכן לא יכול לעשות שימוש חוזר בחפץ שהופק תחת מדיניות אחרת.

## תוצאות נטולות חריגים וזרימת בקרה מובנית

Forge Web Script מייצג תוצאות הניתנות לשחזור עם הספרייה הסטנדרטית
ספירות `Option<T>` ו-`Result<T, E>`. השתמש ב-`match` כדי לטפל בכל גרסה;
`throw`, `try` ו-`catch` ברמת המקור אינם מבנים ניתנים להפעלה. ה
טפסים מובנים `for`, `while` ו-`do while` הם זרימת בקרה ניתנת להפעלה v1;
הם אינם מבנים חריגים או איטרטורים. `Result` יש בדיוק את
גרסאות `Ok(T)` ו-`Error(E)`.

פונקציות איטרטור משתמשות ב-`iter fn`, מחזירות `Iterator<T>` ומשעות ב-`yield`:

```fws
export iter fn forward(source: Iterator<i32>) -> Iterator<i32> {
  loop value = source.next() { yield value; }
}
```

המהדר חושף ייצוא איטרטור דרך תוכנת JavaScript תואמת
מתאם `next()`. כל קריאה מחזירה `{ value, done: false }` עבור ערך ו
`{ value: undefined, done: true }` בהשלמה; שיחות עוקבות נשארות
להשלים. `Iterator<T>.next()` מוקלד כ-`Option<T>`, כך איטרטורים משורשרים
חייב לשמור על סוג האלמנט וחוזה הבעלות.

## אופטימיזציה ופרופילי יעד

אופטימיזציה של שחרור יכולה להחיל פתיחה מוכחת של איטרטור, הטבעת שיחה טהורה,
ניתוח קריאות זנב, וקיפול מותנה בטוח. השתמש בהנחיית `noinline`
כאשר גבול פונקציה חייב להישאר גלוי. יכולת ייבוא ורישום
הן תופעות לוואי הניתנות לצפייה ואינן מסודרות מחדש. תכונות היעד ניתנות להצטרפות
קומפיל קלט ונרשמים במניפסט ABI ובמפתח המטמון:

```ts
const artifact = compileForgeWebScript({
  source,
  fileName: "runtime.fws",
  compilerVersion: "1.0.0",
  optimization: "release",
  targetFeatures: { simd: true, tailCall: true, memory64: true },
  compilerHints: { iteratorUnrollLimit: 4 },
});
```

`threads` ו-`atomics` חייבים להיות מופעלים עבור פלט אטומי של זיכרון משותף;
שילובים לא נתמכים מייצרים אבחון. מניפסט memory64 משתמש ב-`u64`
כתובות וערכי מצביע-אורך-u64. במצב ניפוי באגים, מטמון מוגדר עשוי
מתמיד דטרמיניסטי `<key>.optimized.wat`, `<key>.unoptimized.wat`,
`<key>.optimized.wasm`, ו-`<key>.unoptimized.wasm` חפצים. Cache כותב
הם תוספים ואינם זמינים או מטמונים כושלים אינם נכשלים בהידור.

## פרופילי קישור חוצי פרויקטים

FWS תומך בשני פרופילי קישור ראשיים לניהול תלות בין פרויקטים:

- `linkProfile: "static"`: מודולים חוצי פרויקט משטחים ליחיד
  חפץ גרף סורק. זה מאפשר אופטימיזציה סטטית אגרסיבית
  (פרופיל `static-aggressive`) ומבטל את בדיקת מודול זמן הריצה ב-
  עלות גודל החפץ.
- `linkProfile: "dynamic"`: גבולות מקור-מודול מפורשים נשמרים.
  `ForgeWebScriptDynamicLinkCache` משמש לפתרון מודולי מפענח בזמן ריצה,
  עם כתובות פונקציה מאוחסנות במקש על ידי חפץ וזהות מניפסט. זה
  משתמש בפרופיל האופטימיזציה `dynamic-conservative`, שהוא בטוח יותר עבור
  הפצות מודולריות.

## התייחסות לקסיקלית

דקדוק הצ'ק-אין הקנוני הוא
[`src/grammar/forge-web-script.ebnf`](../../../../src/grammar/forge-web-script.ebnf).
הסיכומים המילוניים והמנתח להלן מסבירים את החוזה הציבורי v1; את
חפץ EBNF הוא סמכותי כאשר פרט יישום אינו ברור.

רווח לבן אינו משמעותי למעט המחרוזות הפנימיות. `//` מתחיל תגובה ש
רץ עד סוף הקו. `/*` מתחיל הערת בלוק שמסתיימת בהערה הבאה
`*/`; הערות חסימה עשויות להשתרע על שורות. הערות הן טריוויה ואינן נכנסות ל
דקדוק. המזהים מתחילים ב-`A-Z`, `a-z` או `_`, וכן
המשך עם אותם תווים או ספרות עשרוניות. מזהים הם
תלוי רישיות. מילים שלמים הם רצפים עשרוניים לא שליליים; v1 עושה זאת
אין לקבל תחביר מילולי הקסדצימלי, אוקטלי או נקודה צפה ב-
תת-קבוצת אתחול. מחרוזות משתמשות במירכאות כפולות ורק בריחות תואמות JSON:
`\\`, `\"`, `\/`, `\b`, `\f`, `\n`, `\r`, `\t` ו-`\uXXXX` עם בדיוק
ארבע ספרות הקסדצימליות. מחסומי שורות גולמיים ואסקייפ לא חוקיים הם מילוניים
שגיאות; השתמש ב-`\n` או `\r` במקום זאת. ערכי מחרוזת הם ערכי UTF-8.

המילים השמורות הן `as`, `capability`, `case`, `catch`, `class`,
`constructor`, `default`, `do`, `else`, `enum`, `extends`, `export`, `for`,
`fn`, `if`, `impl`, `import`, `inline`, `interface`, `iter`, `let`, `likely`,
`loop`, `match`, `module`, `new`, `noinline`, `return`, `struct`, `switch`,
`throw`, `trait`, `try`, `unlikely`, `while` ו-`yield`. `true` ו-`false`
הם מילים בוליאניות. סימני פיסוק הם
`{ } ( ) [ ] : ; , | .`; מפעילים הם
`! % * + - / < <= == != > >= && || = -> => ::`.

כל טווח אבחון הוא טווח חצי קוד פתוח-אופסט `[start, end)` ב-
מחרוזת UTF-16 TypeScript המקורית (הקיזוזים סופרים יחידות קוד UTF-16), עם
שדות שורה ועמודה מבוססים אחד. ה
הטמעת bootstrap מדווחת על קיזוז ונתוני שורה/עמודה יחדיו, כך שא
מתאם Vite יכול לייצר אבחון ממופת מקור ללא ניתוח חוזר.

הסורק שומר הערות כאסימוני `comment` כך שהערות תיעוד יכולות
להיות מחובר לפונקציות, בעוד שהחלטות מנתח מדלגות על כל הטריוויה. מפעילים
עם קידומות משותפות נבחרות לפי ההתאמה הארוכה ביותר. בקלט שגוי את
הסורק צורך אזור תחום, פולט את האבחון `FWS-LEX-*` היציב, ו
ממשיך לאסימון EOF בודד; התנהגות התאוששות זו היא חלק מהדקדוק
חוזה. החזית TypeScript מודד את כל ההיסטים ביחידות קוד UTF-16;
שלבי בתים המתארחים בעצמם חייבים להמיר טווחי בתים של UTF-8 לפני פרסום ה
חוזה סמלי משותף.

### הערות תיעוד פונקציה

הערת בלוק שהמפריד הפותח שלה הוא `/**` היא הערת תיעוד.
הוא מצורף להצהרת `fn` או `export fn` ברמה העליונה הבאה כאשר רק
רווח לבן והערות רגילות מתרחשים בין ההערה להצהרה:

```fws
/**
 * Adds one to a value.
 *
 * @param value The value to increment.
 * @return The incremented value.
 * @deprecated Use `increment` in new code.
 */
export fn add(value: i32) -> i32 {
  return value + 1;
}
```

הערות תיעוד לפני יבוא יכולות, יבוא מקור, מבנים,
תקצירים, ממשקים או הצהרות אחרות שאינן פונקציות נמחקות. הם כן
לא להעביר לפונקציה מאוחרת יותר. אם מתרחשות מספר הערות תיעוד
לפני הצהרה אחת, נעשה שימוש בהערת התיעוד הקרובה ביותר (האחרונה);
הערות `//` ו-`/* ... */` רגילות אינן מחליפות אותו. תיעוד הוא
מוכר רק ברמה העליונה; הערות בתוך גופי פונקציה לא
מטא נתונים של פונקציות. הערת בלוק ללא הפסקה מייצרת את המילונית היציבה
אבחון `FWS-LEX-003` ושחזור מנתח נשארים זמינים למשך שאר
המקור.

למטא נתונים המנורמלים של AST יש צורה זו:

```ts
interface ForgeWebScriptDocumentation {
  readonly description: string;
  readonly tags: readonly ForgeWebScriptDocumentationTag[];
}

interface ForgeWebScriptDocumentationTag {
  readonly name: string;
  readonly subject?: string;
  readonly text: string;
}
```

המנרמל מסיר את המפרידים `/**` ו-`*/`, המובילים את הרווח הלבן,
עיטור `*` מוביל אופציונלי בכל שורה, ורווח לבן מסביב. רץ
של רווח לבן להתמוטט לרווח אחד. שורות תיאור לפני התג הראשון
מקובצים לפסקאות; שורות ריקות נשארות מעברי פסקה. תג מתחיל
בשורה שמתחילה ב-`@`, ושורות עוקבות לא ריקות ממשיכות את
תג קודם. סדר התגים והתגים הכפולים נשמרים.

צורות התגים הנפוצות הן:

| טופס תג | שדות מובנים |
| -------------------------------------------------------- | -------------------------------------------- |
| `@param name text`, `@arg`, `@argument`, או `@parameter` | `name` הוא `subject`; השאר הוא `text` |
| `@typeparam name text` | `name` הוא `subject`; השאר הוא `text` |
| `@throws type text` או `@exception type text` | `type` הוא `subject`; השאר הוא `text` |
| `@return text` או `@returns text` | `text` בלבד |
| `@deprecated text` | `text` בלבד |

טפסים אחרים של `@name` מתקבלים ונשמרים כתגיות מסודרות במקום
דווח כאבחון. אין להם נושא משוער; הטקסט הנותר שלהם
נשמר. שמות התגים הם תלויי רישיות.

עבור צרכני עורכים, אותם מטא נתונים מוצגים באופן דטרמיניסטי כמו ה-
תיאור ואחריו כל תג לפי סדר המקור, עם שורות ריקות ביניהן
חלקים. נושא נפלט בין שם התג לטקסט שלו, לדוגמה:

```text
Adds one to a value.

@param value The value to increment.

@return The incremented value.

@deprecated Use `increment` in new code.
```

התיעוד הוא מטא נתונים של ניתוח, לא סמנטיקה של שפה ניתנת להפעלה. ייתכן
יישמר ב-AST וב-IR עבור צרכני שירותי שפה, אך לא
להשפיע על ניתוח הצהרות, בדיקת סוגים, הנמכה או התנהגות בזמן ריצה.
התיעוד אינו נכלל בחתימות ובמניפסטים של ABI, שנוצרו
הצהרות וחפצי מטעין, Wasm/WAT, גיבוב תוכן בר הפעלה, ו
דרישות יכולת. לכן שינוי רק הערת תיעוד עושה זאת
לא לשנות את ה-ABI של המודול או את חוזה ההפעלה שנוצר.

## דקדוק המקור

חפץ ה-EBNF שצ'ק-אין המקושר למעלה מתאר את המילונית המלאה,
אתחול, חוזה מצטבר מורחב וחוזה התאוששות. הקטע הבא
מתאר את משטח האתחול v1 עבור קוראים שאינם זקוקים לקובץ המלא.
הדקדוק משתמש ב-`*` וב-`?` במובן הרגיל של EBNF:

```ebnf
module       = { import | function } ;
import       = "import", "capability", string, "as", identifier,
               "(", [ parameters ], ")", "->", type, ";" ;
sourceImport = "import", string, "as", identifier, ";" ;
function     = [ "export" ], "fn", identifier, "(", [ parameters ], ")",
               "->", type, block ;
parameters   = parameter, { ",", parameter } ;
parameter    = identifier, ":", type ;
block        = "{", { statement }, "}" ;
statement    = "let", identifier, ":", type, "=", expression, ";"
             | "return", [ expression ], ";"
             | "if", expression, block, [ "else", block ]
             | "while", expression, block
             | "for", "(", [ for-clause ], ";", expression, ";",
               [ for-clause ], ")", block
             | "do", block, "while", expression, ";"
             | identifier, "=", expression, ";"
             | expression, ";" ;
for-clause   = "let", identifier, ":", type, "=", expression
             | identifier, "=", expression
             | expression ;
type         = "bool" | "bytes" | "f32" | "f64" | "i32" | "i64"
             | "string" | "u32" | "u64" | "unit" ;
expression   = literal | identifier | call | unary | binary ;
call         = identifier, "(", [ expression, { ",", expression } ], ")" ;
unary        = ( "!" | "-" ), expression ;
literal      = integer | string | "true" | "false" ;
```

אופרטורים בינאריים עוקבים אחר רמות העדיפות האלה, מהחזק לחלש ביותר:
`* / %`, `+ -`, הזמינו השוואות, שוויון, `&&` ו-`||`. מפעילים הם
שמאל-אסוציאטיבי. ביטויים בסוגריים שמורים ל-bootstrap הבא
עדכון; מהדר חייב להוציא אבחון ניתוח ולא בשקט
מקבל אותם היום.

קטע זה הוא הדקדוק של **bootstrap**. זה מכסה מודולים מוגדרי קובץ,
יבוא יכולות/מקור, חתימות פרימיטיביות, שיחות, ערכים מקומיים,
ביטויים, `if`/`else` מובנה, `while`, `for` בסגנון C, `do while`, וכן
`return`. טפסי הלולאה הם חלק מחוזה האתחול הניתן להפעלה; בלבד
מילות החריג השמורות `throw`, `try` ו-`catch` נדחות בתור
מבנים ניתנים להפעלה. הצהרות וערכים מצטברים להלן הם
חוזה **מורחב** ואין להתייחס אליו כאל איות חלופי עבורו
דקדוק האתחול.

### דקדוק מצטבר מורחב

החוזה המורחב מוסיף מבנים בלתי ניתנים לשינוי, רישומים מתויגים, סוגים גנריים,
ממשקים, ערכי פונקציות, מילולי אוסף, אינדקס ו-`match`.
צורות המקור העיקריות שלהם הן:

```ebnf
aggregate    = struct | enum | interface ;
struct       = "struct", identifier, [ generic_parameters ], "{",
               { identifier, ":", type, ";" }, "}" ;
enum         = [ "export" ], "enum", identifier, [ generic_parameters ], "{",
               variant, { ",", variant }, [ "," ], "}" ;
variant      = identifier, [ "(", [ parameters ], ")" ] ;
generic_parameters = "<", generic_parameter, { ",", generic_parameter }, ">" ;
generic_parameter  = identifier, [ ":", identifier ] ;
type         = primitive | identifier, [ "<", type, { ",", type }, ">" ]
             | "[", type, ";", integer, "]"
             | "Fn", "<", type, ",", type, ">" ;
constructor  = identifier, "::", identifier, "(", [ expression ], ")" ;
match        = "match", expression, "{", match_arm, { ",", match_arm }, "}" ;
match_arm    = pattern, "=>", expression ;
pattern      = "_" | identifier, [ "(", [ identifier, { ",", identifier } ], ")" ] ;
```

בנאים מוסמכים כגון `Result::Ok(value)` ו
`Result::Error(message)` פתרון נגד הגרסה המצטברת ואימות
סוגים של אריות ושדה. גרסאות `Result<T, E>` הסטנדרטיות הן בדיוק
`Ok(T)` ו-`Error(E)`; `Option<T>` נשאר `Some(T)` ו-`None`. פונקציה
הערך משתמש ב-`fn name` ובסוג `Fn<parameter, result>` מוצהר, למשל
`let callback: Fn<i32, i32> = fn increment;`. ערכי הפונקציה נבדקים על ידי
חתימת הפונקציה שהפניה אליה וניתן להתקשר רק עם arity תואם
וסוגי טיעונים.

כריכות התאמה הן מקומיות לזרוע שלהן: `Result::Ok(item) => item` כריכות
`item` תוך בדיקת ביטוי זה בלבד. שמות מחייבים חייבים להיות ייחודיים ב-an
הזרוע והספירה שלהם חייבים להתאים לשדות הווריאציות שנבחרו; הם לא דולפים
לזרועות אחים או לתפקוד שמסביב.

## סוגים וסמנטיקה

ל-V1 יש את הסוגים הפרימיטיביים `bool`, חתום `i32`/`i64`, ללא חתימה `u32`/`u64`,
`f32`/`f64`, `string`, `bytes` ו-`unit`. אין מספרים מרומזים
המרות. אופרנדים אריתמטיים חייבים להיות בעלי אותו סוג מספרי; השוואות

ללא ערך.

### חתימות אוסף

חוזה הגבייה המורחב הוא מבני ומבוסס על כונס נכסים; זה כן
לא להוסיף שיטות אובייקט שרירותיות. מערכים קבועים כתובים `[T; N]` ו
וקטורים כמו `Vector<T>`. החתימות הנתמכות הן:

| מקלט | שיטה | חתימה |
| ----------- | --------------- | ----------------------- |
| `Array<T>` | `length` | `() -> u32` |
| `Array<T>` | `get` | `(u32) -> Option<T>` |
| `Array<T>` | `set` | `(u32, T) -> Array<T>` |
| `Array<T>` | `iter` | `() -> Iterator<T>` |
| `Vector<T>` | `length` | `() -> u32` |
| `Vector<T>` | `get` | `(u32) -> Option<T>` |
| `Vector<T>` | `set` | `(u32, T) -> Vector<T>` |
| `Vector<T>` | `push` או `add` | `(T) -> Vector<T>` |
| `Vector<T>` | `pop` | `() -> Option<T>` |
| `Vector<T>` | `iter` | `() -> Iterator<T>` |

האיות `add` הוא בכוונה כינוי תאימות לוקטור
`push`; זו לא שיטת מערך. האינדקסים הם `u32`, ארגומנטים של אלמנט חייבים
להתאים ל-`T`, וערכי ההחזר חייבים להתאים לחתימות למעלה. אמנות לא נכונה,
סוגי ארגומנטים, סוגי מקלטים ושיטות לא ידועות הן שגיאות בדיקת סוגים.
מילוליות ריקות דורשות סוג רכיב הקשרי, בעוד מערך/וקטור לא ריק
מילוליות מסיקים את סוג היסודות שלהם באופן רקורסיבי ודוחים אלמנטים מעורבים. א
ליטרל של מערך קבוע חייב להכיל בדיוק רכיבי `N`.

מקומיים הם בהיקף פונקציות, מאותחלים פעם אחת בדיוק, ולא ניתן לקרוא אותם קודם לכן
ההצהרה שלהם. הצהרה מקומית לא מצילה שם קיים: שכפול
שמות הם שגיאה. פונקציות וכינויים ליכולות חולקים מרחב שמות של מודול אחד
וחייב להיות ייחודי. קריאה חייבת לתת שם לפונקציה שהוצהרה או מיובאת
היכולת, וסוגי האריות והטיעונים שלה חייבים להתאים בדיוק.

משטח זרימת הבקרה v1 בנוי `if`/`else`, `while`, `for` בסגנון C,
`do while`, ו-`return` מוקדם. `for` סעיפים הם הצהרות מפורשות ועשויות
לא להציג מחלקות, מקלטים או מוטציה מרומזת מחוץ ללולאה
סביבת ערכית מקומית. אין תוצאה סתמית של נפילה: כל
נתיב נגיש בפונקציה שאינה `unit` חייב להחזיר את הסוג המוצהר. ה
בודק bootstrap מדווח על שגיאות סוג החזרה; ניתוח נגישות הוא א
נדרש מעקב לפני הכרזת מהדר תואם לחלוטין ל-v1.

FWS הוא ללא שיעור בכוונה. `class`, `constructor`, `extends`, `impl`,
`new` ו-`trait` שמורות ונדחו עם אבחון יציב
`FWS-PARSE-052`; מבנים בלתי ניתנים לשינוי, תקצירים מתויגים, ממשקים ופונקציות
ערכים הם האלטרנטיבות המוכוונות ערכיות הנתמכות. האירוח העצמי המבוים
החוזה שומר את המהדר TypeScript הצ'ק-אין כ-Seed בעוד מהדר FWS
וחוזי זמן ריצה עוברים אתחול בהדרגה.

## מודולים מוגדרי קבצים, ייבוא ​​מקור וייצוא

אין הצהרת `module` מקוננת. כל קובץ `.fws` הוא מודול ושלו
השם היציב נגזר ממזהה הקובץ המנורמל שלו. למשל,
`src/time.fws` בפרויקט `/workspace/app` כולל מזהה מודול `src/time`. מקונן
תחביר `module name { ... }` נדחה עם אבחון העברה.

יבוא של מודול מקור שונה מייבוא ​​של יכולות מארח:

```fws
import "./math.fws" as math;
import capability "clock.now" as now() -> i64;
```

מתאם Vite פותר יבוא מקור דרך גרף המודול שלו. תלות
בתוך פרויקט אחד מקושרים סטטית כברירת מחדל. ברירת מחדל של קצוות חוצי פרויקט
לטעינה דינמית וניתן להגדיר אותו כ-`static` או `dynamic` עם מפורש
תצורת קישור פרויקט-שורש. חסרים מודולים, מחזורים שאינם נתמכים על ידי
מצב קישור נבחר, והתנגשויות זהות הן אבחון גרף.

קישורים סטטיים משטחים יצוא אורחים שניתן להגיע אליהם לחפץ אחד. התנגשויות ייצוא
נדחים באופן דטרמיניסטי (`FWS-LINK-003` עבור חתימות כפולות ו
`FWS-LINK-004` עבור חתימות לא תואמות); המקשר לא בשקט
מרחב שמות או החלפת פונקציות אורח. קישורים דינמיים נשארים מודול נפרד
גבולות ונרשמים כייבוא של מודול מקור במניפסט ABI, לעולם לא
כיכולות מארח סביבה.

רק הצהרות שקדמו ל-`export` הן ציבוריות. שמות הייצוא יציבים,
מחרוזות רגישות רישיות וממוינות לקסיקוגרפית בקובץ שנוצר
מתגלה. פונקציות פרטיות עשויות להיות בשימוש על ידי פונקציות מיוצאות אך לא
גלוי למארח. אין ייצוא תווים כלליים ואין ייבוא ​​סביבה.

לייבוא ​​יכולות יש שם מצוטט בבעלות מארח וכינוי אורח מקומי:

```fws
import capability "clock.now" as now() -> i64;

export fn current_time() -> i64 {
  return now();
}
```

שם היכולת המצוטט, הכינוי, שמות/סוגי פרמטרים וסוג התוצאה הם
הכל כלול במניפסט. היבוא הוא דטרמיניסטי: כינויים כפולים או
הצהרות יכולות נדחות, ושמות יכולות נדרשות
ביטול כפילות ומיון. המארח מספק יישומים לפי שם יכולת;
האורח אינו יכול לגלות או לקרוא ליכולת שנעדרת ממנה
מתגלה.

## יכולת לוגית ABI

Forge Web Script משתמש בגבול _לוגי_ בהשראת WASI, לא בטענה של מלא
תאימות WASI. יכולת היא פונקציית מארח צרה ומפורשת כגון
`clock.now`, `random.bytes` או `storage.read`. שמות היכולות הם בבעלות
הפלטפורמה, ולכל שם יש חתימה בגרסה נפרדת. אובייקטי DOM,
`window`, `document`, Node מובנים, לקוחות רשת ודפדפנים גלובליים אחרים
הם אף פעם לא תלות אורחים סביבתיים.

המעמיס מבצע את הבדיקות הבאות לפני המופע:

1. פורמט המניפסט, גרסת השפה וגרסת ה-ABI נתמכים.
2. כל יכולת נדרשת קיימת ברישום המארח.
3. לכל יכולת שסופקה יש את החתימה המוצהרת המדויקת ולא מוצהרת
   ייבוא אורחים מתקבל.
4. הצהרות זיכרון, מקצה, ייצוא וייבוא הן פנימיות
   עקבי.

גילוי יכולת הוא פעולת מארח מפורשת. מארח עשוי לחשוף א
מלאי יכולת לקוד יישום, אך האורח מקבל רק את
יבוא המוצהר על ידי המודול שלו. יכולות חסרות או נדחות נכשלות עם א
מלכודת `CapabilityDenied` בזמן טעינה; הם לא הופכים ל-`undefined` או א
ללא הפעלה שקטה.

## ערכים, זיכרון ליניארי ובעלות

המודול משתמש בזיכרון ליניארי WebAssembly אחד עם 64 עמודי KiB ו-Little-endian
ערכים סקלרים. ערכים סקלרים ממפים באופן הבא:

| Forge Web Script | ייצוג WebAssembly |
| ----------------- | ------------------------------------------ |
| `bool` | `i32`, כאשר `0` הוא שקר ו-`1` נכון |
| `i32`, `u32` | `i32` |
| `i64`, `u64` | `i64` |
| `f32`, `f64` | תואם WebAssembly float |
| `unit` | אין ערך תוצאה |
| `string`, `bytes` | שני ערכי `u32`: מצביע ואז אורך בתים |

המניפסט מצהיר על אותו מיפוי ב-`valueRepresentations`. א
צמד אורך מצביע תמיד מסומן כטווח ללא סימן לפני קריאה או
כתיבה: `pointer <= memory.byteLength` ו-`length <= byteLength - pointer`.
אורך אפס חוקי ועשוי להשתמש בכל מצביע בגבולות, כולל הסוף של
זיכרון. בדיקה נכשלת לוכדת עם `MemoryOutOfBounds` ולעולם לא חושפת א
ערך מפוענח חלקית.

המודול שנוצר מייצא `fws_alloc(size: u32) -> u32`,
`fws_dealloc(pointer: u32, size: u32) -> unit`, ו
`fws_realloc(pointer: u32, oldSize: u32, newSize: u32) -> u32` בתור הבעלות
גבול למאגרים. בקיצור, הפעולה היא
`fws_realloc(pointer, oldSize, newSize) -> pointer`. המתקשר שמקצה חוצץ הוא הבעלים שלו וחייב
הקצה או הקצא מחדש באמצעות אותו מודול וגודלו הנוכחי המדויק.
המקצה מחדש מעדיף לשנות את גודל הקצאת המים הגבוהים הנוכחית במקום,
כולל הצטמקות וגדילה כאשר זיכרון ליניארי יכול לגדול. אחרת זה
מקצה תחליף, מעתיק בדיוק `min(oldSize, newSize)` בתים, ו
משחרר את ההקצאה הישנה לפני החזרת המצביע החלופי. א
תוצאה בגודל אפס תקפה, ובקשה בגודל שווה מחזירה את המקור
מצביע. יישומי מארח חייבים להעתיק בתים של קלט לפני שיחת האורח
מחזיר אלא אם המניפסט מציג במפורש מאגר שאול עתידי
חוֹזֶה. אסור לקוד אורח לשמור מצביע בבעלות המארח לאחר שיחה מארח.
מלכודות כשל בהקצאה או צמיחה עם `MemoryExhausted`; מצביע לא חוקי או
מלכודות טווח גודל עם `MemoryOutOfBounds`; ומצביע מעופש, לא נכון
`oldSize`, מלכודות חינם כפולות או לא חוקיות עם `InvalidOwnership`. אלה
בדיקות מתרחשות לפני מוטציה, והקצאה מחדש שנכשלה משאיר את המקור
הקצאה ובייטים ללא שינוי.

חריגים מארח מומרים ל-`HostError` עם שם היכולת ו-an
קוד שגיאה מארח אטום. מלכודות אורחים לעולם לא הופכות להחזרה רגילה
ערכים. מארחים עשויים לרשום פרטי מלכודת, אך אסור להם לחשוף סודות או גולמיים
חריגים בדפדפן לקוד אורח לא מהימן.

### פעולות זיכרון נבדקות בבעלות אורחים

מודולי מקור של FWS שמיישמים ערימת אורח מצבית עשויים להשתמש במהדר שבבעלות המהדר
פעולות `memory_alloc(size: u32) -> u32`,
`memory_dealloc(pointer: u32, size: u32) -> unit`,
`memory_realloc(pointer: u32, oldSize: u32, newSize: u32) -> u32`,
`memory_load_u32(address: u32) -> u32`, ו
`memory_store_u32(address: u32, value: u32) -> unit`. פעולות אלו הן
הורד ישירות למקצה המודול או זיכרון WebAssembly שנבדק
הוראות; הם אינם יבוא מארח ואינם חושפים את מדינת האורח
TypeScript.

המקצה משתמש באותו חוזה בעלות ומלכודת כמו `fws_alloc` ו
`fws_realloc`. טעינה או חנות דורשת טווח שלם של ארבעה בתים בתוך
זיכרון ליניארי נוכחי; מלכודות טווח לא חוקיות עם `MemoryOutOfBounds` לפני כן
הפעולה יכולה לבצע חלקית. `memory_realloc` משמר את הראשון
`min(oldSize, newSize)` בייט ומחזיר מצביע בבעלות אורח, בזמן המתקשרים
חייב להשתמש במצביע המוחזר ובגודלו הנוכחי המדויק עבור פעולות מאוחרות יותר.
מתקן הזיכרון הממלכתי מתחת
`packages/forge-web-script/src/fixtures/stateful-memory.fws` הוא ההתאמה
מתקן עבור חתימות אלה, שימוש חוזר במקצה, רקורסיה, איפוס וגבולות
מלכודות.

קוראי בתים בבעלות מהדר מספקים גם גרסאות אינדקס לא חתומות לאורח
ממשקי קצה המייצגים קיזוז מקור כנקודות אחיזה: `bytes_length_u32(value:
bytes) -> u32` and `bytes_byte_at_u32(value: bytes, index: u32) -> u32`. הם
השתמש באותם בדיקות גבולות אורך מצביע כמו החתומים `bytes_length` ו
`bytes_byte_at` פעולות ואינן יבוא מארח. הקצה הקדמי של WebLua משתמש
פעולות אלה לשמור על קיזוז lexer וכתובות זיכרון אורח באחד
בדק את הדומיין `u32`.

### חוזה WASM ABI גולמי וחוזה ESM שנוצר

הייצוג למעלה הוא ה-WASM הגולמי היציב ABI. זה בכוונה
ברמה נמוכה ואינו משתנה כאשר חזית ה-JavaScript שנוצרה הופכת ליותר
ארגונומי:

```text
raw string value: (pointer: u32, length: u32)
raw bytes value:  (pointer: u32, length: u32)
```

חפץ ESM שנוצר באמצעות מהדר מקרין את ABI לתוך API של JavaScript:

```ts
type ForgeWebScriptBytes = readonly [pointer: number, length: number];

interface ForgeWebScriptExports {
  readonly memory: WebAssembly.Memory;
  readonly fws_alloc: (size: number) => number;
  readonly fws_dealloc: (pointer: number, size: number) => void;
  readonly fws_realloc: (
    pointer: number,
    oldSize: number,
    newSize: number,
  ) => number;
  readonly fws_reset: () => void;
  readonly echo: (value: string) => string;
  readonly processBytes: (value: ForgeWebScriptBytes) => ForgeWebScriptBytes;
}
```

כל הצהרה שנוצרה, כולל יבוא יכולות וקישור דינמי
מייצא, משתמש ב-`string` עבור ערכי FWS `string`. ה-`load` ו-
עטיפות `loadSync` מקודדות מחרוזות JavaScript כ-UTF-8, העברת מצביע באורך
צמדים ל-WASM ABI ללא שינוי, ומפענח מחרוזות שהוחזרו בחזרה ל-JavaScript
מחרוזות. הפענוח משתמש במפענח UTF-8 קטלני: בתים פגומים של אורח הם an
שגיאת גבול מפורשת במקום תווים חלופיים.

ארגומנטים של מחרוזת עבור קריאה אחת מקודדים תחילה ונארזים לאחד רציף
הקצאת אורחים. זה שומר על ה-ABI הגולמי ללא שינוי תוך הימנעות מאורח אחד
הקצאה ועותק JavaScript ל-WASM לכל ארגומנט. טיעונים סקלרים נשמרים
הדרך המהירה הישירה שלהם. `bytes` אינו מומר בכוונה ל-`Uint8Array`:
המתקשרים ממשיכים לעבור ולקבל `ForgeWebScriptBytes`, ו-`memory` הוא
חשוף כך שהמתקשרים יוכלו לקרוא או לכתוב טווחי בתים גולמיים באמצעות זיכרון המודול
וכללי בעלות.

המתאם שנוצר הוא הבעלים של מאגרים זמניים שנוצרו עבור ארגומנטים של מחרוזת ו
תוצאות מחרוזת. זה מפענח תוצאה לפני שחרורה, ואז משחרר כל אחת
טווח זמני בדיוק פעם אחת בנתיב `finally` על הצלחה, מלכודות אורחים, מארח
חריגים, וכשלים בפענוח. יכולת מארח עם ערכי מחרוזת מקבל
מחרוזת JavaScript ועשויה להחזיר מחרוזת JavaScript; העטיפה מבצעת את
הקצאת אורחים ועותק UTF-8 עבור ערך החזרה זה. קוד מארח עדיין חייב להעתיק
קלט `bytes` גולמי לפני החזרה אלא אם מניפסט עתידי מצהיר במפורש
חוזה מאגר מושאל. `load` ו-`loadSync` חושפים את אותו הדבר שנוצר
חוזה; הם שונים רק בתזמון אתחול המודול.

שינוי הקרנת JavaScript זו אינו משנה את `valueRepresentations`, את
ABI באורך מצביע גולמי, גרסת ABI או ה-hash הגולמי של תוכן WASM.
החפץ שנוצר שומר על ייצוג WASM מוטבע אחד שפוענח בעצלתיים;
`load` ו-`loadSync` חולקים אותו במקום להגשים מטען נפרד
עותקים. כתוצאה מכך, בדיקות מטעין אסינכרון מול סינכרון צריכות להשוות התנהגות
והצהרות, בעוד שבדיקות תוכן-hash דטרמיניסטיות צריכות לחלץ את ה-raw
בייטים של WASM ללא תלות בגודל מקור ה-ESM שנוצר או ביישום הטוען
פרטים.

## פורמט מניפסט

לכל מודול שנוצר יש מניפסט ABI יציב תואם JSON לצדו
חפץ WASM ומטען ESM מודפס:

```json
{
  "format": "forge-web-script-module",
  "languageVersion": "1.0",
  "abiVersion": "1.2",
  "moduleName": "src/clocked",
  "exports": [{ "name": "current_time", "parameters": [], "result": "i64" }],
  "imports": [
    {
      "capability": "clock.now",
      "alias": "now",
      "function": { "name": "now", "parameters": [], "result": "i64" }
    }
  ],
  "sourceImports": [],
  "requiredCapabilities": ["clock.now"],
  "memory": {
    "pageSize": 65536,
    "addressType": "u32",
    "ownership": "caller-owned",
    "stringEncoding": "utf8",
    "byteArrayRepresentation": "pointer-length",
    "allocatorExport": "fws_alloc",
    "deallocatorExport": "fws_dealloc",
    "reallocatorExport": "fws_realloc"
  },
  "valueRepresentations": { "i64": "i64", "string": "pointer-length-u32" },
  "trapModel": "explicit-trap",
  "standardLibrary": { "regexBytecodeVersion": "bytecode-1" }
}
```

המניפסט בפועל מכיל את כל ערכי הייצוג הפרימיטיביים, לא רק
אלה המשמשים את הדוגמה. מפתחות JSON ליצוא, יבוא ויכולות הם
יציב על פני בנייה חוזרת; מפות מקור ו-hash של תוכן נפלטים על ידי
מתאם המהדר ואינם חלק מהתאמת חתימות ABI.

שדה המניפסט `standardLibrary` מתעד זהויות של ספרייה בבעלות מהדר.
עבור ביטוי רגיל, `regexBytecodeVersion` ו-`regexCorpusHash` אופציונלי הם מטמון
וכניסות חפצים. המקור המנורמל, גרסת המהדר, אופטימיזציה
מצב, גרף מודול, תצורת קישור, זהות ספרייה סטנדרטית ומטא נתונים
יש לבצע סדרה של corpus hash בסדר יציב לפני חיפוש מטמון. זהה
כניסות מייצרות טבלאות קוד בתים זהות, מניפסטים, הצהרות, WAT ו-
גיבוב תוכן; שינוי כל קלט זהות הוא החמצת מטמון. קורפוס חשיש הוא
בבעלות החבילה המספקת את הקורפוס ואין להסיק מהמארח
מצב זמן ריצה.

## גבולות מהדר ו-CLI

החזית הציבורית TypeScript שומרת על חוזי קצה ותזמור נפרדים
מהפליטה. הוא מקבל קובץ מקור או גרף פתור, מייצר מובנה
אבחון בתוספת IR מוקלד, ומאציל יצירת WebAssembly/WAT ל
`@mission-platform/forge-web-script-wasm`. הקצה האחורי מאמת את הבייטים שלו לפני כן
החזרתם; שגיאות מדכאות פלט בר הפעלה. שימוש במתאם Vite וב-LSP
החזית ואינם צריכים להיות תלויים ב-Node CLI.

עבור זרימות עבודה של מערכת קבצים, התקן את `@mission-platform/forge-web-script-cli` ו
השתמש בבינארי `forge-web-script` העצמאי שלו:

```text
forge-web-script check <entry.fws> [--root <directory>] [--project-root <directory>]
forge-web-script compile <entry.fws> --out-dir <directory>
  [--root <directory>] [--project-root <directory>]
  [--link-mode static|dynamic] [--capability <name>] [--optimization debug|release]
```

`check` מאמת את כניסות המקור והגרפים מבלי לכתוב קבצים. מוצלח
`compile` כותב בדיוק `<entry>.wasm`, `<entry>.wat`, `<entry>.abi.json`,
`<entry>.d.ts`, `<entry>.js` ו-`<entry>.map` לספריית הפלט שנבחרה.
ה-CLI משלב ומשנה את שם הסט המלא רק לאחר שהאבחון ברור, אז
מקור שגוי, קצוות גרפים לא פתורים, יכולות מוכחשות ושגיאות ABI
לא להשאיר חפץ הפעלה ולהחזיר סטטוס שאינו אפס. הזמנת פלט,
מניפסט JSON, WAT, הצהרות, נתוני מטעין, מפות מקור ו-hash של תוכן
הם דטרמיניסטיים עבור תשומות זהות.

## שילוב בדיקות Vitest ו-Vite

השתמש ב-`@mission-platform/forge-web-script-vitest` כאשר חבילת Vitest צריכה
טען חפצי מהדר, אבחון מובנה, התנהגות Wasm, קישורי גרפים,
או חוזה המודול Vite שנוצר. שיטות הרתמה הישירות שלו (`compile`,
`compileSource`, `compileGraph`, `inspect`, `load`, `loadSync`, וכן
`checkVmParity`) להאציל לציבור חוזי מהדר/זמן ריצה; שלה
`defineForgeWebScriptVitestConfig` עוזר מתקין את ההפקה
`forgeWebScriptPlugin` תוך שמירה על תוספים והגדרות Vite לצרכן.
ראה [בדיקה בפלטפורמת המשימה](../../../../../../docs/locales/he/testing.md#forge-web-script-tests) עבור
דוגמאות לתצורה ומתקן.

הרתמה מקבלת פונקציות מארח רק באמצעות מפות יכולות מפורשות
לפי שמות יכולות מניפסט, למשל:

```ts
const exports = await harness.load<{ current: () => bigint }>(
  "capabilities/clock-now.fws",
  {
    "clock.now": { now: () => 123n },
  },
);
```

יבוא מוצהר חסר ויבוא מסופק לא מוצהר הם כשלים. מבחן
פרויקטים שמייבאים `.fws` או שאילתות חפצים וירטואליים שלו צריכים להוסיף את
תת נתיב להכרזה מסוג סוג בלבד
`@mission-platform/forge-web-script-vitest/forge-web-script` שלהם
רשימת TypeScript `types` או נקודת כניסה של סוג בדיקה.

הרתמה המשותפת מתבססת מתחת
`packages/forge-web-script-vitest/fixtures/` הם הקורפוס חוצה החבילות עבור
מודולים תקפים, אבחון, יכולות, גרפים וזוגיות באירוח עצמי.
אביזרי חבילה מקומיים נשארים מתאימים למהדר, זמן ריצה ותוסף
מבחנים המממשים פרטים פרטיים.

`checkVmParity` מדווח על חוזה זוגיות של lex-stage מוגבל ב-
מצב `interpret`, `jit` או `aot`. הצהרת זוגיות, טביעות אצבעות, ספירת צעדים,
ומטא נתונים של שחזור AOT, אך אל תתייחסו לדוח זה כאל שרירותי
ביצוע Compiled-FWS VM; טעינת Wasm נשארת בדיקת התנהגות בזמן הריצה.

## אבחון

אבחון הוא רשומות מובנות עם `code`, `severity`, `phase`, `message`,
`fileName`, ומקור `span`; רשומות הניתנות לפעולה עשויות לכלול גם `hint`.
השלב הוא אחד של `lex`, `parse`, `type-check` או `abi`. קוד v1 יציב
משפחות כוללות:

| משפחת קוד | המשמעות |
| ------------- | ----------------------------------------------------------------------------------------- |
| `FWS-LEX-*` | תווים/escapes לא חוקיים, מסימי שורה גולמית של מחרוזת, או מחרוזות/הערות שלא נגמרו |
| `FWS-PARSE-*` | תחביר מודול, הצהרה, משפט או ביטוי לא חוקי |
| `FWS-TYPE-*` | סוג פרימיטיבי לא חוקי, שם, אופרטור, ארגומנט או החזרה |
| `FWS-ABI-*` | שמות כפולים, יכולות שנדחו, ייצוא או יבוא |
| `FWS-REGEX-*` | דפוסי ביטוי רגולרי לא נתמכים או פגומים בבעלות מהדר |

שגיאות מונעות יצירת חפצים. אזהרות ואבחון מידע כן
לא לשנות סמנטיקה. סדר אבחון הוא סדר מקור, ואחריו שלב
סדר לאבחון המצורף לאותו טווח. מתאם Vite חייב לשמר
הקוד והטווח היציבים בעת העברת שגיאה ל-Vite.

## חוזה התאמה של Bootstrap

יעד המהדר v1 מוגבל בכוונה לשפה ולמשטח ABI
מתועד כאן. תוכנית נמצאת בתת-קבוצת האתחול אם היא משתמשת באחת כזו
מודול, הכללים המילוניים שלמעלה, טיפוסים פרימיטיביים, ערכי `string`/`bytes`,
פונקציות מיוצאות במפורש, יבוא יכולות, הצהרות מקומיות, שיחות,
ביטויים, `if`/`else`, `while`, `for` בסגנון C, `do while` ו-`return`.
החוזה המצטבר המורחב נבדק בנפרד ומוסיף
structs, enums, טיפוסים גנריים, ערכי אוסף, ערכי פונקציות ו
`match`; אסור שזה יהיה תלוי בדפדפן מרומז או Node גלובלי.

`packages/forge-web-script/src/fixtures/bootstrap.ts` הוא קובץ ההפעלה
קורפוס התאמה. מתקנים מקובלים חייבים לאמת ללא אבחון שגיאות;
מתקנים שנדחו חייבים לדווח על קודי האבחון היציבים הרשומים שלהם ותקפים
טווחי מקור. הטמעות בשפות אחרות יכולות לצרוך את אותו מתקן
לעצב ולהשוות ASTs מנורמלים, אבחון ו-JSON מניפסט. המתקן
חבילה היא יעד התאמה, לא תמונת מצב ספציפית ליישום.

קורפוס המקור המשותף ב
`packages/forge-web-script-vitest/fixtures` מכסה את אותו גבול:
`valid/collections.fws` תרגילים אוסף מילוליים, אינדקס, הקשר
וקטורים ריקים, `length()`, ומחרוזות בריחה חוקיות;
`valid/aggregates.fws` מפעיל ערכי פונקציות, `Result::Ok` מוסמך ו
בנאים `Result::Error`, וכריכות התאמה מקומית לזרוע; ו
`diagnostics/collections.fws` מפעיל קריאות איסוף לא חוקיות ומצטבר
אבחון בנאי/קשירה. גם מתקן האיסוף מורכב
דרך רתמת Wasm המשותפת; תחביר מצטבר נשמר כחזית
מקור התאמה עד להפעלת הורדת Wasm מצטברת עבור הרתמה הזו.

## מדיניות תאימות

השפה והגרסאות העיקריות של ABI אינן תואמות כברירת מחדל. מטעין עשוי לקבל
אותו ABI עיקרי עם גרסה מינורית גבוהה יותר רק כאשר המפיק מסמן את
שדות חדשים אופציונליים והצרכן מתעלם משדות לא ידועים בבטחה. הסרת א
ייצוא, שינוי סוג, שינוי בעלות או שינוי יכולת
החתימה דורשת גרסת ABI שבירה וחייבת להידחות על ידי מעמיסים
לא ליישם את זה. ABI `1.2` הוא גרסה כל כך שבירה למרות השמירה
המספור `1.x`: ייצוא הזיכרון הנדרש `fws_realloc` אינו אופציונלי,
ומניפסטים של ABI `1.1` אינם משודרגים בשקט. הוספת יכולת לעולם לא
משנה בשקט מודול קיים: הוא דורש הצהרת מניפסט חדשה ו
אישור מארח.

גרסאות מהדר אינן גרסאות ABI. המהדרים חייבים לכלול את הגרסה שלהם ב
ה-Compilation input ו-hash artifact, אבל מעמיסים משווים בין השפה ל-ABI
גרסאות בתוספת חתימת המניפסט. בדיקת תאימות שנכשלה היא א
אבחון זמן טעינה, לא נפילה של זמן ריצה. מודולי Rust ו-AssemblyScript
להמשיך להשתמש במעטפת הקיימים ובחוזי ABI במהלך הדו-קיום
תקופה; Forge Web Script אינו מפרש מחדש או מחליף אותם.

תאימות ספרייה סטנדרטית של Regex נפרדת בכוונה מה-Regex של המארח
תאימות. החוזה והמהדר של Forge bytecode מגדירים את המקובל
תחביר ואבחון יציב; ה-VM ההפניה משמש רק כדי לאמת את
התנהגות הכי שמאלה/עקיבה לאחור, קיזוז לכידה של UTF-16 וזקיף `-1` לא מוגדר
עד שה-VM האחורי יהיה זמין. דפדפן או Node התנהגות ביטוי רגיל
הוא רק אורקל דיפרנציאלי, ולא ה-TypeScript reference VM ולא a
מארח API של ביטוי רגיל עשוי לבצע קריאת ספריית ייצור סטנדרטית.
שינוי מספור opcode, פריסת חריץ לכידה, תחביר נתמך, אבחון
קודים, או סמנטיקה תואמת דורשים גרסה חדשה של קוד בתים של ביטוי רגולרי וגרסה חדשה
זהות חפץ. עד התאמה ל-backend/זמן ריצה והעברת מספרי טלפון
הוכחות מושלמות, יישום הטלפון של AssemblyScript נשאר
אורקל רגרסיה מפורש מדור קודם ולעולם לא מעורבב עם חפץ Forge.

## דו קיום והגירה

Forge Web Script הוא יעד הייצור של הנייטרלי
חפץ `@mission-platform/code-scanner`. גרף הסורק שלו מקשר באופן סטטי
מקורות מפענח ה-QR, המטריצה והברקוד ל-WebAssembly עצמאי אחד
חפץ; הפרופיל הדינמי שומר על גבולות מודול מקור ומפורשים
מטמונים פתרו יצוא. ארגז Rust `code-scan` נשאר זמין בתור א
יישום מקורי/רפרנס ואינו תלוי זמן ריצה של החבילה.
חבילות ה-QR, המטריצה ​​והברקוד הציבוריות שומרות על עטיפות מודפסות משלהן;
ממשקי API אלה אינם מופנים בשקט דרך גרף הסורק.

ה-`codecMigrationFixture` ב
`packages/forge-web-script/src/fixtures/codec-migration.ts` הוא הראשון
מתקן התאמה בצורת מתאם codec. זה מצהיר
`codec.barcode.encode(payload: string) -> bytes`, מייצא את `encode_payload`, מאמת את
ABI באורך מצביע, ומשתמש במארח הניתן להזרקה כדי לכתוב פלט בבעלות המתקשר.
זה נשאר בכוונה מתקן ABI צר: המארח יכול להשתמש בדטרמיניסטי
מזויף עבור מבחני התאמה בזמן שהמתקן מוכיח את Forge Web Script
גבול. שוויון Codec ייצור עדיין דורש התאמת וקטורים ו
מדידות ביצועים, לא רק שם פונקציה תואם.

המעטפת מדור קודם מייצאת את `encode(symbology, data)` ומחזירה
`Uint8Array | undefined`; המתקן מייצא `encode_payload(payload)` ו
מחזיר זוג `bytes` בבעלות ABI. ההבדל המכוון הזה שומר על
גבול יכולת מפורש: מתאם העברה עשוי למפות את המורשת
סמליות/נתונים מתקשרים ליכולת המוצהרת, אך המתקן לא
להעמיד פנים ששני הייצוא עדיין ניתנים להחלפה מבחינה התנהגותית.

### שער ראיות וביטול

עבודת הגירה צריכה לרשום ארבע השוואות עצמאיות עבור כל מועמד:

1. התנהגות מיוצאת נגד וקטורים מוזהבים משותפים, כולל קלט לא חוקי ו
   מקרי גבול;
2. בטיחות ABI, כולל בדיקות מניפסט/גרסה, מניעת יבוא, בדיקות גבולות,
   המרת מלכודת, ובעלות חיץ;
3. יציבות חפצים שנוצרה, כולל גיבוב הניתנים לשחזור, הצהרות,
   מפות מקור וטעינת דפדפן/Node; ו
4. מדידת ביצועים בבניית שחרור מייצגת המכסה קומפילציה
   זמן, גודל חפץ, אתחול ושיחות במצב יציב.

מתקן ההגירה מספק כרגע את חלקי ה-ABI והחפצים של זה
ראיות. בדיקות עטיפות הברקוד והמפענח הקיימות נשארות
אורקל התנהגות ורגרסיה מורשת; להפעיל אותם לצד המתקן במקום זאת
מאשר להתייחס למתקן כאל אמת מידה חלופית. Forge Web
אסור לסקריפט לבטל משימוש נתיב Rust או AssemblyScript עד שעומס עבודה יעבור
לכל ארבע ההשוואות בשתי סביבות מארחות נתמכות, יש מסמך מתועד
נתיב החזרה לאחור, ואין לו ממצאי ABI או אבטחה לא פתורים. הוצאה לפירוק אז
דורש חלון תאימות הוכרז ומתאם או מדריך הגירה;
הסרה מחייבת שחרור גדול לאחר מכן.

## חוזי צבירה והוצאה לפועל ללא כיתות

החוזה המורחב ללא שיעורים מוסיף ערכי `struct` בלתי ניתנים לשינוי, מתויג `enum`
ערכים, הצהרות `interface` בזמן הידור מבני, פרמטרים גנריים
עם גבולות ממשק, ערכי פונקציות, מילוליות/שיטות אוסף, ו
`match` ביטויים/הצהרות. בנאים מוסמכים של enum משתמשים ב-`Type::Variant`
וכריכות גפרורים הן זרוע מקומיות; למשל,
`Result::Ok(item) => item` קושר את `item` רק בזרוע זו. התקן
חוזה `Result<T, E>` משתמש ב-`Ok(T)` וב-`Error(E)`, לא ב-`Err(E)`.
עדכוני מבנה הם טרנספורמציות ערך טהורות; לא מבנים ולא ממשקים
יש בנאים, זהות, ירושה, מקלטים או שיגור בזמן ריצה. כל
נסה להכריז על מבנים מוכווני מחלקה/אובייקט (כולל `class`,
`constructor`, `extends`, `impl`, `new` ו-`trait`) נדחתה עם יציבות
אבחון `FWS-PARSE-052`.

פריסות מצטברות נרשמות במניפסט לפי סדר שמות קנוני. מבנה
השדות מסודרים, ערכים מיושרים של ארבעה בתים; פריסות enum מתחילות ב-4 בתים
מפלה. הבעלות על השדה היא מפורשת (`owned`, `borrowed` או `shared`) וכן
ברירת המחדל היא אחסון בלתי ניתן לשינוי בבעלות. ערכים גנריים מתמחים לכל בטון
סוג; ייצוגים מבוססי תיאור שמורים לאיטרטור מפורש או
גבולות ממשק ומיוצגים על ידי רשומות התמחות.

חוזה bytecode של VM אינו תלוי בקצה העורפי. A `ForgeWebScriptVmModule`
מכיל פונקציות מוקלדות, קבועים, פריסות מצטברות, התמחויות,
יבוא יכולות, טווחי מקור וזיכרון ליניארי של 64 KiB
גבול `fws_alloc`/`fws_dealloc`/`fws_realloc`. `interpret`, `jit` ו-`aot` הם ביצוע
מצבים על אותה סמנטיקה של הוראה/ערך/מלכודת; מפתחות מטמון JIT ו-AOT
חפצים כוללים מהדר ו-hash של מקור. ניתן להתקשר ליכולות בלבד
כאשר קיים במניפסט המודול.

מצב זמן ריצה תגובתי הוא נתונים: מדדי ישויות משתמשים במוני יצור,
חנויות רכיבים ועולמות הם תמונת מצב בלתי ניתנת לשינוי, ומערכות חוזרות לעולם
מעברים. אותות, מנויים, דרישות שאילתות, סדר דטרמיניסטי,
ושלבי מתזמן מוגבל הם ערכים מפורשים. שילוב מארח ECS דורש
אותו גבול יכולת מוצהר כמו כל ייבוא FWS אחר.

## גבול היקף

היישום v1 הוא חזית TypeScript בתוספת WebAssembly דטרמיניסטית
אחורי, נחשף דרך חזית התאימות וה-Node CLI העצמאי.
גופי ההתאמה והחפצים שנוצרו הם יעד התאימות.

קומפילציה מתארחת עצמית (הפעלת המהדר כתוכנית FWS) היא במפורש
נתמך על ידי חוזה v1 זה של משטח ללא מחלקות וביצוע קוד byte VM
מודל, אך הוא אינו נדרש לתקינות ה-V1 ABI והשפה
גבול. תכונות שפה עשירות יותר, החלפת חלודה קיימת או
עומסי עבודה של AssemblyScript ואבולוציות אחרות של מהדר שאינן v1 נמצאות מחוץ לזה
חוזה.

## חתך כלי עבודה וגבול אתחול

הפלאגין CLI, Vite, שירות השפה וה-LSP כולם צורכים את המהדר הציבורי
חוזה שירות. העברת lexer היא בכוונה LSP-first: הצ'ק-אין
דקדוק EBNF מגדיר את חוזה האסימון TypeScript, שירות השפה ו
מתאמי עורך הם גבול הקבלה הראשון, ומהדר/חזית או
אסור לזוז בבעלות באירוח עצמי עד לסוגי אסימונים, אבחון, סמלים,
טווחי השלמה, ריחוף ו-UTF-16 תואמים. ה-FWS בתחומה הנוכחית
שלב lex/token נשאר נתיב זוגיות תאימות בעוד שה-TypeScript lexer
ושער שירותי השפה עוברים הגירה; זה לא סמכות הדקדוק.

לאחר ששער ה-LSP ירוק, אותו דקדוק יועבר ל-FWS/VM lexer
ולאחר מכן לשלב הנתח-מודול התחום. החזית הנותרת, מקשר,
שלבי אופטימיזציה, מניפסט ופליטת Wasm עדיין מגובים בזרע הזה
שחרור; גבול זה הוא מכוון והוא חשוף כמו
`ForgeWebScriptSelfHostedStageReport` במקום להיות מוצג כמושלם
אירוח עצמי.

ה-CLI בוחר במצב VM עם `--vm-mode interpret|jit|aot`. התוסף Vite
ואפשרויות סביבת עבודה של שירות שפה משתמשות ב-`selfHostedVmMode` המקביל
ערך. כל שלושת המצבים מבצעים את אותו bytecode ומשווים את טביעת האצבע של lex
עם התייחסות הזרע העצמאית. אי התאמה או מלכודת VM הופכת ליציבה
`FWS-BOOTSTRAP-001` אבחנתית ומונעת מחפץ Wasm לא חוקי
נפלט. `interpret` מיועד לבדיקות מהירות, בעוד `jit` ו-`aot` הם
מצבי התאמה/פיתוח; הידור Wasm נשאר הייצור הרגיל
חפץ ונתיב זמן ריצה.

קישור גרפים, הצהרות, מפות מקור, מניפסטים של ABI, גיבוב דטרמיניסטי,
בעלות על זיכרון ליניארי, מניעת יכולת, ערכי איסוף/ECS ומפורש
יכולות מתזמן אסינכרון נשארות כפופות לחוזים הציבוריים הקיימים.
מתאמי הכלים אינם מוסיפים ממשקי API מארח סביבתיים או שיגור אובייקט מרומז.
Microtasks ו-Web Workers זמינים רק באמצעות מתזמן מוצהר
היכולות, והסדר שלהן נשאר מפורש ודטרמיניסטי. צרכנים
צריך להתייחס לדוח ה-VM כאות זוגיות/התאמה עד לפרסום מאוחר יותר
להעביר שלבי מהדר נוספים מאחורי אותו גבול FWS.
