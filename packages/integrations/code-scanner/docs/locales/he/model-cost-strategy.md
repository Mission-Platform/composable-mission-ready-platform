# אסטרטגיית מודל ועלות — מאמץ של קורפוס ZXING בכיסוי מלא

תרגום בסיוע מכונה מהמקור האנגלי הקנוני. יש לבדוק ידנית בעת הצורך. שמות חבילות, פקודות, נתיבים ומזהים טכניים נשארים ללא שינוי.

> packages/integrations/code-scanner/docs/model-cost-strategy.md: [packages/integrations/code-scanner/docs/model-cost-strategy.md](../../model-cost-strategy.md)
> שפה: עברית (he)

מסמך זה לוכד את **מטריצת המודלים** המבוקשת עבור עבודת הקופסה השחורה של ZXING ("השתמש בסוכנים של
מודלים שונים כדי לקבוע כיצד להשיג זאת בצורה הטובה ביותר בעלות האפקטיבית ביותר"). הוא רושם איזו שכבת דגם היא הטובה ביותר
מתאים לכל שלב מסירה, כך שבכל מקום בו קיים מנגנון האצלה ניתן לנתב את העבודה לזול ביותר
שכבה מסוגלת - ובמקום שבו סוכן יחיד עושה את העבודה, הוא מנחה לאן הכי הרבה מאמץ (והמודל הכי מסוגל)
צריך לבזבז.

## הגדרות שכבה

- **שכבה A (העליון / המסוגל ביותר)** - חשיבה חדשה של ראיית מחשב ופענוח כבד מפרט: המאתרים החדשים (MaxiCode
  רשת משושה + bullseye, אשכול שורות PDF417, מכלול שורות מוערמות של GS1 DataBar) וה-Reed–Solomon /
  מתמטיקה לתיקון שגיאות (GF (929) עבור PDF417, GF (64) עבור MaxiCode, קומבינטוריקה של RSS). אלה החלקים ביותר
  סביר לטעות בדרכים עדינות והכי קשה להתאושש מטיוטה ראשונה גרועה.
- **שכבה B (אמצע)** - העברה מוגדרת היטב מההפניה של ZXING: טבלאות סימבוליות, מקודדים, הלוך ושוב שנוצרו
  בדיקות, רתום היגיון, והכללת מטעין PNG. צורת התשובה ידועה; העבודה זהירה
  תמלול וחיווט.
- **שכבה C (זול / מכאני)** - עותק בכמות גדולה, קבצי ייחוס, פיגומים בסיסיים, מסמכים ולוח החיווט
  (תגיות פורמט, `FORMAT_NAMES`, האיחוד `ScanFormat`).

## שלב → מיפוי שכבות

| במה | עבודה | שכבה |
| ---------------------------------- | ------------------------------------------------------- | ---- |
| 1 קורפוס ספק + מעמיס + רתמה | העתקה/ייחוס (C), מטעין + לוגיקה לרתום (B) | C→B |
| 2 הגדל את קצב הקריאה בפורמט נתמך | כוונון איתור + נתיבי ניסיון חוזר | א → ב |
| 3 משפחת GS1 DataBar | טבלאות/מקודדים (B), איתור RSS-14 + RS (A) | א/ב |
| 4 PDF417 | טבלאות/מקודד (B), מאתר סריקת שורות + GF(929) EC (A) | א/ב |
| 5 MaxiCode | איתור רשת משושה + GF(64) RS (A), טבלאות (B) | א/ב |
| 6 Wire-up + JS + מסמכים | boilerplate/docs + חיווט (C), wasm rebuild + עשן (B) | C→B |

## עקרון העלות

למקסם את נתח Tier-C / Tier-B - היציאה המכנית (טבלאות, מקודדים, בדיקות הלוך ושוב, חיווט) היא החלק הארי של
העבודה בפורמט החדש - ושמרו את תקציב ה-Tier-A לשלושת המאתרים החדשים באמת ותיקון השגיאות שלהם
מתמטיקה, שבה טעויות של דגם חלש יותר יקרות לאיתור ולתיקון. ספייק קצר יכול לסמן דגם זול יותר
יציאת מפענח אחת לפני ביצוע השכבה לשאר.

## איך זה הסתדר

- **שלב 6** (שלב זה) הוא המקרה המובהק ביותר Tier-C→B: הארכה
  `FORMAT_NAMES` והאיחוד `ScanFormat` הוא מכני (C); בנייה מחדש של ה-wasm וכתיבת עשן העלאה/זרם
  חבילה עם קורא PNG קטן היא עבודה בינונית שצוינה היטב (B). לא היה צורך בהנמקה ברמה א' ברגע שהיליד
  מפענחים (שלבים 3-5) היו במקום.
- **שלבים 3-5** כל אחד מפוצל בצורה נקייה: הטבלאות/מקודדים של ZXING ומבחנים הלוך ושוב היו תמלול Tier-B, בעוד
  מאתרים וריד-סולומון (GF (929), GF (64), קומבינטוריקה של RSS) היו ליבת Tier-A - עקבית עם המטריצה
  למעלה.

> היישום השתמש בביקורות מואצלות ממוקדות עבור נכונות RSS, ה
> קוראי דו-ממד מוערמים, ופליטת גרפי QR. ביקורות אלה אישרו את
> הגביל את גבול הקורא המופחת ובידד את כשל ה-QR ל-Forge Web
> פולט סקריפט במקום להסוות אותו בנסיגה. המטריצה נשארת ה-
> מדריך למעברי זוגיות עתידיים היכן שהקורפוס החסר והמפענח יכולים לעבוד
> להתפצל בבטחה.

## גבול תכנון מחדש הנוכחי

הבסיס שהושלם ועבודת 1D/RSS השתמשו ב-Tier B עבור יציאות בצורת ZXing ו
סקירה שכבה עבור קומבינטוריקה של RSS, סיכומי בדיקה והתנהגות זיכרון מוגבל. ה
קוראי דו-ממד מקושרים נוכחיים הם יישומים מופחתים בכוונה, כך טוענים
שוויון ZXing מלא ידרוש מפענח וגלאי Tier-A חדשים במקום זאת
יותר מעבודות תיעוד או מתקן.

החקירה הבאה בעלת הערך הגבוה ביותר היא כשל פולט QR של פלינט:
גרף ה-QR העצמאי תקף, אך מקשר את המפענח שלו לסורק
הגרף נכשל `FLINT-WASM-001` לפני זמן הריצה. עד שגבול המהדר הוא
נפתרה, מתקן Tier-C ועבודת API חייבת לשמור על QR כעצמאי מפורש
המקרה ואסור להמיר תווים מקומיים מופחתים לתביעות זוגיות.
