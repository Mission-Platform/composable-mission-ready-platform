本文档捕获了 ZXING 黑盒语料库工作所需的 **模型分层矩阵**（“使用
各种模型来确定如何以最有效的成本实现这一目标”）。它记录了哪个模型层最好
适合每个交付阶段，以便无论存在授权机制，工作都可以路由到最便宜的
有能力的层 - 当单个代理完成工作时，它会指导最努力的地方（以及最有能力的模型）
应该花费。

## 等级定义

- **A 层（顶级/最有能力）** — 新颖的计算机视觉推理和规格繁重的解码：新的定位器 (MaxiCode
  六边形网格 + 牛眼、PDF417 行聚类、GS1 DataBar 堆叠行组件）和 Reed–Solomon /
  纠错数学（PDF417 的 GF (929)，MaxiCode 的 GF (64)，RSS 组合）。这些是最重要的部分
  可能会出现一些微妙的错误，并且最难从糟糕的初稿中恢复过来。
- **B 层（中）** — 来自 ZXING 参考的详细指定移植：符号表、编码器、生成的往返
  测试、利用逻辑和 PNG 加载器泛化。答案的形状是已知的；工作很仔细
  转录和接线。
- **C 层（廉价/机械）** — 批量复制、归属文件、基线脚手架、文档和接线样板
  （格式标签、`FORMAT_NAMES`、`ScanFormat` 联合）。

## 阶段 → 层映射

|舞台|工作|等级 |
| ---------------------------------- | ------------------------------------------------------- | ---- |
| 1 供应商语料库 + 装载机 + 线束 |复制/归属 (C)、加载器 + 线束逻辑 (B) | C→B |
| 2 提高支持格式的读取率 |定位器调整+重试路径| A→B |
| 3 GS1 DataBar 系列 |表/编码器 (B)、RSS-14 定位器 + RS (A) | A/B |
| 4 PDF417 | 4表/编码器 (B)、行扫描定位器 + GF(929) EC (A) | A/B |
| 5 最大代码 |六角网格定位器 + GF(64) RS (A)、表格 (B) | A/B |
| 6 连线 + JS + 文档 |样板/文档 + 接线 (C)、wasm 重建 + 烟雾 (B) | C→B |

## 成本原则

最大化 C 层/B 层共享 — 机械移植（表、编码器、往返测试、接线）是大部分
新格式的工作——并为三个真正新颖的定位器及其纠错保留一级预算
数学中，检测和修复较弱模型的错误的成本很高。短峰值可以对更便宜的模型进行基准测试
一个解码器端口，然后再提交其余层。

## 结果如何

- **第 6 阶段**（本阶段）是最明确的 C→B 级案例：扩展
  `FORMAT_NAMES` 和 `ScanFormat` 联合机械 (C)；重建 wasm 并编写上传/流烟雾
  带有小型 PNG 阅读器的套件是明确的中层工作 (B)。一旦本地人知道了，就不需要 A 级推理了
  解码器（第 3-5 阶段）已就位。
- **阶段 3-5** 每个阶段都清晰地分开：ZXING 表/编码器和往返测试是 B 级转录，而
  定位器和 Reed–Solomon（GF (929)、GF (64)、RSS 组合）是 A 级核心 — 与矩阵一致
  上面。

> 实施过程中使用了针对 RSS 正确性的集中委托审查，
> 堆叠式 2D 读取器和 QR 图形发射。这些评论证实了
> 有界的减少读者边界并将 QR 故障隔离到 Forge Web
> 脚本发射器而不是用后备屏蔽它。矩阵仍然是
> 未来奇偶校验指南，其中缺失的语料库和解码器工作可以
> 安全分开。

## 当前重新规划边界

已完成的基础和 1D/RSS 工作使用 B 层用于 ZXing 形端口和
A 级审查 RSS 组合、校验和和有限内存行为。的
当前链接的 2D 阅读器有意减少实现，因此声称
完整的 ZXing 奇偶校验需要新的 A 级解码器和检测器通道
比更多的文档或固定工作。

下一个价值最高的调查是 Flint QR 发射器故障：
独立的 QR 图形有效，但将其解码器链接到扫描仪
图在运行前失败 `FLINT-WASM-001`。直到编译器边界是
已解决，C 级固定装置和 API 工作必须将 QR 保持为显式独立的
情况，并且不得将减少的本地固定装置转换为平价声明。
