# סקריפטים של שירות משותף

תרגום בסיוע מכונה מהמקור האנגלי הקנוני. יש לבדוק ידנית בעת הצורך. שמות חבילות, פקודות, נתיבים ומזהים טכניים נשארים ללא שינוי.

> docs/configs/scripts-config.md: [docs/configs/scripts-config.md](../../../configs/scripts-config.md)
> שפה: עברית (he)

מדריך זה נשאר בכוונה בשכבת תיעוד הפרויקט: `scripts/`
היא חבילת סביבת עבודה פרטית המכילה תזמור מאגר ולא א
ספרייה הניתנת לפרסום.
פקודות ספציפיות לחבילה וליישום נשארות מתועדות לצדן
בעלות על חלל עבודה.

פלטפורמת המשימה שומרת על קבוצה של סקריפטים של כלי שירות משותפים בשורש
ספריית `scripts/`. סקריפטי החבילה שלהם רשומים כמשימות Turbo, בעוד
השורש `package.json` חושף עטיפות נוחות המעבירות ל-Turbo.

## סקירה כללית

סקריפטים אלו הופכים משימות monorepo נפוצות לאוטומטיות, כגון הגדרת פיתוח מקומי ואימות בנייה. תרגום
החילוץ מוגדר על ידי כל אפליקציה או חבילה ומתוזמר משורש המאגר עם Turborepo.

## סקריפטים זמינים

### Turbo משפחות משימות

השתמש במעטפת השורש עבור כלי השירות של המאגר למטה. כל פקודה היא א
משימה נפרדת, כך Turbo יכול לגיבוב ולתזמן אותה באופן עצמאי:

| פקודה | מטרה | מדיניות מטמון |
| :----------------------------------- | :---------------------------------------------------------------- | :---------------------------------------------------------- |
| `pnpm validate` | הפעל את הבדיקה הסטטית של הרכיב העצמאי דרך Turbo. | המשימה נשמרת באופן עצמאי.                           |
| `pnpm docs:generate` | צור תיעוד עזר לחבילות ותוספות.           | קובצי עזר שנוצרו נשמרים במטמון.                       |
| `pnpm validate:exports` | אמת מפות ייצוא חבילות ומטרות בנויות.                     | ניתן למטמון כאשר הכניסות שלו לא משתנות.                    |
| `pnpm validate:component-properties` | בדוק הצהרות מאפיינים של רכיבים מול סגנונות מקור.      | ניתן לקובץ שמור וללא פלט.                                  |
| `pnpm validate:inventory` | הפק את מלאי אימות זמן הריצה.                         | חפצים שניתנים למטמון תחת `.artifacts/runtime-validation/`. |
| `pnpm validate:framework` | אימות כיסוי זמן ריצה של מסגרת.                              | חפצים שניתנים למטמון תחת `.artifacts/runtime-validation/`. |
| `pnpm validate:app` | אימות כיסוי זמן ריצה של אפליקציה.                            | חפצים שניתנים למטמון תחת `.artifacts/runtime-validation/`. |
| `pnpm validate:target` | אמת יעדי Storybook מוגדרים.                            | חפצים שניתנים למטמון תחת `.artifacts/runtime-validation/`. |
| `pnpm validate:runtime` | הפעל את חבילת אימות זמן הריצה המלאה.                            | לא מאוחסן במטמון מכיוון שהוא מתחיל תהליכי ריצה חיצוניים.    |

### חילוץ i18n (`i18n:extract`)

כל אפליקציה או חבילה שבבעלותם תרגומים מספקים סקריפט `i18n:extract` ו-`i18next.config.ts`. הפקודה כותבת
חבילות מרחב שמות תחת ספריית `locales/<locale>/` של כל סביבת עבודה. הפעל חילוץ עבור כל סביבות העבודה המוגדרות מ
שורש המאגר:

```bash
pnpm i18n:extract
```

### יצירת אישורי מפתח (`generate-dev-cert.ts`)

מייצר אישורי SSL/TLS מקומיים לפיתוח HTTPS. זה שימושי לבדיקת תכונות הדורשות מאובטח
הקשר (למשל, גישה למצלמה דרך `@mission-platform/code-scanner`).

```bash
pnpm exec tsx scripts/generate-dev-cert.ts
```

### אימות רזולוציית מסגרת (`verify-framework-resolution.mjs`)

מאמת שיצוא חבילות `@mission-platform/*` נפתר כהלכה לבניית המסגרת המיועדת (Vue, React וכו')
מבוסס על תנאי היצוא של הסביבה.

```bash
node scripts/verify-framework-resolution.mjs
```

### הפקת תיעוד (`docs:generate`)

יצירת התיעוד היא משימה Turbo בבעלות `@mission-platform/scripts`.
אפליקציית ה-Docs תלויה במשימה הזו במפורש, אז פיתוח ובנייה
פקודות אינן מתחילות לבנות Turbo מקונן.

## שיטות ביצוע

### דרך מנהל החבילות

כלי עזר בשימוש תכוף זמינים בתור סקריפטים מגובים Turbo ב-`pnpm`
שורש `package.json`:

```bash
pnpm run <script-name>
```

עבור הזמנה בהיקף של חבילה, השתמש ישירות ב-Turbo:

```bash
pnpm exec turbo run validate:exports --filter=@mission-platform/scripts
```

### ביצוע ישיר

ניתן להפעיל סקריפטים בודדים של TypeScript באמצעות `tsx` או `node --experimental-strip-types`:

```bash
pnpm exec tsx scripts/<filename>.ts
```

## הנחיות לתרומה

בעת הוספת סקריפט משותף חדש:

- הצב אותו בספריית `scripts/`.
- השתמש ב-TypeScript במידת האפשר.
- אם הסקריפט תלוי בחבילות חיצוניות, הוסף אותן ל-`package.json` של סביבת העבודה שבבעלותך.
- תיעוד את מטרת הסקריפט והשימוש בקובץ זה.
- הוסף ערך תואם בבסיס `package.json` אם זה כלי עזר בשימוש תכוף.
