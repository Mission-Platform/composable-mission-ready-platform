# セッションのセルフレビュー

正規の英語ソースからの機械支援翻訳です。必要に応じて人手で確認してください。パッケージ名、コマンド、パス、技術識別子は変更しません。

> docs/agent-guidance/session-self-review.md: [docs/agent-guidance/session-self-review.md](../../../agent-guidance/session-self-review.md)
> 言語: 日本語 (ja)

タスクが成功したか、失敗したか、実装前に停止したかに関係なく、すべてのセッションの終了時にこのレビューを完了してください。レビューは終了記録であり、現在のタスクを拡張する許可ではありません。

## Outcome Review

以下の簡潔な証拠を記録します。

- 何が試みられ、どのような結果が要求されたか。
- 予想される動作と観察された動作。
- 確認された、反証された、または不確実なままになっている仮定。
- 失敗、ブロックされた作業、リグレッション、および未解決のリスク。
- コマンド、テスト、診断、スキャン、レビュー、およびそれらの結果を含む、実行された検証。
- 最終の差分が焦点を絞っているか、移植可能か、一時的なアーティファクトがないか、リポジトリの規約と一致しているかどうか。
- どのガイダンスが作業を可能にし、どのガイダンスが曖昧で、発見が難しく、重複し、古くなり、または不必要にコストがかかるものでしたか。

機能していた慣例を維持します。観察された問題を仮説や推測的な改善アイデアと区別し、提案された各変更を裏付ける証拠を含めます。

## MCPレビュー

MCP ツールまたはプロファイルが使用された場合は、次の質問に答えてください。

- 選択したプロファイルは、タスクを完了できる最小限のプロファイルでしたか?
- 明示的な書き込みが必要になるまでは、制限付きの読み取り専用検査ツールが好まれていましたか?
- `review_changes` と利用可能なセキュリティ チェックは、提案された突然変異とそのリスクを検査するのに十分でしたか?
- スキーマ、出力制限、ページネーション制限、タイムアウト、またはツールの人間工学によって摩擦が生じたり、有用な証拠が隠蔽されたりしましたか?
- より明確な確認、より狭い境界、より強力な分離、またはより安全なフォールバックを必要とする書き込みパスはありましたか?
- 用語と動作は `mcp/README.md`、`mcp/developer/README.md`、`.ai/mcp/mcp.json`、`scripts/launch-mcp.mjs`、`mcp/developer/src/tools/profiles.ts`、および `mcp/developer/src/tools/index.ts` と一致しましたか?

単に便利だからという理由だけで、より幅広いプロファイルや新しいツールを提案しないでください。観察された安全性、信頼性、または理解の問題を取り除く最小の変更について説明してください。

## 改善の決定

それぞれの改善の機会を分類します。

- **ドキュメントのフォローアップ:** リポジトリの動作は正しいが、ガイダンスが欠落している、不明瞭、重複している、古い、または発見するのが難しい場合に使用します。 `AGENTS.md` または所有トピック ドキュメントに対する最小の更新を提案します。
- **別途承認された実装:** 調査結果により、MCP ランタイム動作、プロファイル、スキーマ、サーバー登録、`.ai/mcp/mcp.json`、ツール、または別の実装の変更が必要な場合に使用します。フォローアップとして記録します。明示的に許可されていない限り、ドキュメントレビューの一部として実装しないでください。
- **変更なし:** 観察が推測である場合、証拠が欠如している場合、または既存の慣例が依然として最も安全で明確な選択肢である場合に使用します。

フォローアップでは、依存関係の方向、明示的な変更境界、移植性、下位互換性、最小権限、および制限された操作を保持する必要があります。証拠をリンクし、所有者、影響を受ける真実の情報源、および最小の安全な次のアクションを特定します。

## 見切り形式

書面によるレビューが必要な場合は、最終的な引き継ぎでこのコンパクトな形式を使用します。

```markdown
### Session self-review
- Outcome: <expected and observed result>
- Evidence: <checks performed and results>
- Assumptions or uncertainty: <confirmed, disproved, or unresolved items>
- Guidance and MCP findings: <what helped or caused friction>
- Follow-up: <documentation, separately authorized implementation, or no change; include evidence>
```
