# エージェントの仕事品質に関するルーブリック

正規の英語ソースからの機械支援翻訳です。必要に応じて人手で確認してください。パッケージ名、コマンド、パス、技術識別子は変更しません。

> docs/agent-guidance/quality-rubric.md: [docs/agent-guidance/quality-rubric.md](../../../agent-guidance/quality-rubric.md)
> 言語: 日本語 (ja)

このルーブリックは、実装前にアプローチを選択するために使用し、レビュー中に結果を評価するために使用します。タスクに適合するあらゆる次元を適用します。ドキュメントのみの変更であっても、シンプルで、保守しやすく、読みやすく、衛生的である必要があります。ルーブリックを主観的なスコアとして扱うのではなく、重要なトレードオフの具体的な証拠を記録します。

## 最小の安全な変更

- 要求された結果と、それを満たすことができる最小の変更を述べます。
- 新しい抽象化よりも既存のリポジトリ パターン、パッケージ、ツール、プロファイル、ドキュメントを優先します。
- 無関係なクリーンアップ、投機的な再設計、未承認の MCP ランタイム変更をタスクから除外します。
- 小規模なアプローチでは正確性、セキュリティ、または必要な検証を維持できないことが証拠に示されている場合にのみ、範囲を拡大します。

## 七次元

### シンプルさ

- ソリューションは、要件を満たすファイル、可動部分、依存関係、状態遷移、およびツール呼び出しを最小限に抑えていますか?
- 既存のコンポーネント、ユーティリティ、トークン、変換、ワークフロー、または MCP 機能を複製するのではなく、再利用しますか?
- 投機的な抽象化、重複した MCP ツール、不必要な構成変更は削除されましたか?

### 複雑

- 新しい依存関係、状態、制御フロー、クロスパッケージエッジ、プロファイル/ツール表面、操作手順、および故障モードを特定します。
- 避けられない複雑さの原因がそれぞれ必要な理由と、より単純な代替案では不十分な理由を説明します。
- 複雑さを所有するパッケージまたはトピックドキュメントにローカルに保ち、重複したソース間でポリシーが拡散することを避けます。

### 信頼性

- 観察可能な期待される動作とそれを証明する証拠を定義します。
- 決定論的な動作、制限された操作、明示的な障害処理、および安全なフォールバックを好みます。
- ネガティブなケースや統合境界を含む、重要なパスを検証します。部分的なフィクスチャ、ソース診断、または分離されたユニットをエンドツーエンドの動作の証拠として扱わないでください。
- 成功を黙って推測するのではなく、失敗、不確実性、未検証の仮定を報告します。

### 保守性

- 構造、命名、依存関係、テスト、ドキュメント、所有権についてはリポジトリの規則に従います。
- 責任をローカルに保ち、各ルールに 1 つの正規ドキュメントを置きます。
- 将来のエージェントが見つける可能性がある永続的な決定と非自明な制約を文書化します。
- 古いリンク、重複したインベントリ、並行実装、および真実の情報源から逸脱する可能性のある文言は避けてください。

### 安全

- 最小権限、リポジトリのルートとパスの境界、シェルフリーの実行、明示的な変更の承認、および秘密の衛生状態を維持します。
- インジェクションを防御し、承認された暗号化と依存関係の実践を使用し、依存関係の方向を保持します。
- 便宜上、既存のセキュリティ スキャンを弱めたり、制限付き/読み取り専用検査をより広範なアクセスに置き換えたりしないでください。
- 該当する変更については、関連する開発者 MCP セキュリティ チェック (`security_scan_secrets`、`security_analyze_code`、`security_audit_dependencies`、`security_audit_supply_chain`、`security_collect_compliance_evidence`、および `security_audit_compliance`) を実行します。

### 衛生

- 差分に焦点を当て、リポジトリの形式、名前、およびワークフロー規則を保持します。
- 既存のファイルやセッション管理のファイルを削除せずに、タスク中に作成された一時アーティファクトを削除します。
- 影響を受けるドキュメントとリンクを更新し、生成されたローカル ファイル、秘密ファイル、または無関係なファイルが含まれていないことを確認します。
- 実行された正確な検証と実行できなかったチェックを報告します。

### 読みやすさと理解力

- 対象となるエージェントがガイダンスをすぐに目を通すことができるように、明確な見出し階層、短いセクション、一貫した用語、直接的な文章を使用します。
- 認知的負荷を最小限に抑える: アクションの前に前提条件を提示し、関連するルールをまとめ、必須の作業と任意の作業を識別し、説明のない相互参照を回避します。
- 明白ではない制約、所有権、優先順位、安全境界、および異常な検証要件の理由を説明します。
- リンク、例、名前、および出力の説明が、非表示のセッション コンテキストなしで理解できることを確認します。
- 独立した理解パスを実行します。別のエージェントがガイダンスに従い、文書だけから正しい次のアクションを選択できますか?

## レビュー記録

重要なタスクの場合は、最終レビューまたは引継ぎでルーブリックの結果を要約します。最小の安全なアプローチ、材料の複雑さ、信頼性の証拠、セキュリティと衛生チェック、および個別に承認されたフォローアップ作業となる可読性の問題について言及します。

関連ポリシー: [リポジトリの安全性と検証](repository-safety-and-validation.md) および [セッションのセルフレビュー](session-self-review.md)。
